# 模块数据归属与联动

当前职责为：现在负责记录，过去负责回看与沉淀，未来负责设计与践行，分身负责索引、整理、分类、调整与应用。前台只显示用户需要查看、确认和编辑的结果；整理和关联由后台完成。

## 前台职责

| 模块            | 主要任务                                         | 不再设置的独立入口                              |
| --------------- | ------------------------------------------------ | ----------------------------------------------- |
| 过去            | 回看经历；把重复模式沉淀为原则并持续修正         | 一级只保留“回看 / 沉淀”；原则编辑收进“调整”入口 |
| 现在            | 记录当下经历，通过对话整理可保存内容             | 不另建一份长期记忆数据库                        |
| 未来            | 设计展示愿景、目标、行动规划；践行维护行动结果   | 一个“新增规划”入口，不设三个新增面板            |
| 分身 · 聊天     | 结合现有经历、认识、方向进行对话，提出待确认内容 | 不再复制各模块的原始数据                        |
| 分身 · 记忆档案 | 关于我、我的模式、我的变化；查看和修正自我理解   | 不展示后台关系维护、统计、标签管理工具          |

记忆档案保留三个横向入口：

| 分组     | 内容                                           | 用户操作                       |
| -------- | ---------------------------------------------- | ------------------------------ |
| 关于我   | 基础信息、偏好与边界、价值与动力、能力与条件   | 搜索、新增、修改、忘记         |
| 我的模式 | 已确认的理解、选择、情绪、关系与行动模式       | 搜索、查看、修正原记录         |
| 我的变化 | 有明确版本关联的认识更新，以此前／现在对照展示 | 搜索、阅读；无依据时显示空状态 |

原则列表只在过去“沉淀”维护，愿景、目标与行动列表只在未来维护。分身聊天继续调用这些信息，但不在档案中再次展示列表。待确认入口跨分类保留，方向候选确认后写回未来的唯一数据仓库。

“方法”由现有原则及其触发条件、实践方式承载，没有另建方法副本库。归类是读取视图：旧八类元数据保留兼容，不再作为档案主导航。

## 唯一数据来源

前台编辑入口的位置不等于数据库归属。

| 数据               | 唯一存储     | 其他模块如何使用                                               |
| ------------------ | ------------ | -------------------------------------------------------------- |
| 经历               | 原始经历记录 | 过去展示；分身按权限读取；通过编号关联认识及行动结果           |
| 模式与理解         | 原有理解记录 | “我的模式”修改直接更新该记录                                   |
| 原则               | 原则库       | 过去“沉淀”维护，分身读取当前版本，行动保留原则编号             |
| 愿景、目标         | 未来数据仓库 | 未来提供统一编辑入口；分身按需读取，行动引用目标，目标引用愿景 |
| 行动               | 行动库       | 未来展示与编辑；分身实时读取视图                               |
| 独立个人信息或认识 | 原子记忆库   | 档案展示；确认后供分身使用                                     |

行动列表不在记忆档案重复展示。修改标题和完成状态不会生成第二份记录。目标—愿景、行动—目标、行动—原则关系均采用明确保存的编号，不凭文字相似自动认定因果。

## 提取、确认与去重

1. 自动提出的持久信息先进入待确认状态，未经确认不当成已知事实。短暂情绪不自动成为长期人格结论。
2. 新增记忆弹窗保留内容编辑；方向类内容可选择保存为愿景、目标或行动。确认弹窗和档案使用同一分组规则。
3. 用户主动在目标、愿景、行动、原则编辑器中保存即为明确提交，不额外弹一次记忆确认。
4. 同一次结构化提取中，完全相同的语句被多个维度命中时，合并为一条候选并保留多个维度和证据；不自动合并不同来源或不同历史记录。
5. 方向候选确认时，规范对象与候选来源映射在一个事务中提交。同一候选的相同确认重试返回原对象；改动内容后重复提交会报错，避免覆盖已确认内容。
6. 已转换的旧独立记忆保留在存储中，但读取时由来源映射排除。其规范对象被修改、完成或删除后，旧文本不会重新作为活动计划出现。不同编号的相似内容不被静默合并。
7. 分组优先尊重规范对象身份，其次识别价值观、边界和偏好，再识别方向，最后区分认识与个人信息。规则属于保守启发式，不代表模型已经理解所有复合句。

聊天中的文字分类与经历模式分析仍有不同的提取入口，后者负责跨经历的认识。两者共享档案归类及规范对象写入规则，但此次未实现跨入口的语义自动合并；混合了偏好与计划的句子可能仍需用户改写后确认。历史重复记录不做不可逆批量清理。

## 来源变化与隐私

- 修改经历正文前，关联的已确认规律和推断退回待确认；关联更新失败会阻止正文修改。正文保存失败时，解释可能仍需重新确认。
- 删除来源的引用清理由原有删除事务处理；读取时过滤不存在端点的关系。
- 来源依据优先读取当前可访问原文；无法读取的来源不回显缓存正文。
- 锁定、加密、未到解锁时间的经历及示例记录不进入新的经历投影。
- 愿景归档、行动放弃后不作为当前活动计划进入分身。完成行动保留历史状态。
- 旧版本的长期推进数据保留兼容展示和操作，不强制改写成新记录；新行动编辑器不再提供旧长期推进类型。

## 备份与恢复

完整备份 v3 包含原始记录、原则、行动、未来数据、理解、独立记忆、关系和标签。未来数据中的 `archiveOrigins` 包含转换的规范对象编号、来源引用及重试指纹，随完整备份恢复；投影视图可由规范数据重建。

继续接受 v2 备份：合并导入保留其缺少的新数据，替换导入按备份恢复。沿用既有加密保险库导出限制；API Key 不纳入记忆备份，本次也不改动已记住的模型配置。

“关于我”的下层分类基于已有维度，多个分类可引用同一条记忆；不复制、不改写原记录。未来统一编辑器在新增时选择愿景、目标或行动，切换保留正文；已有对象按原类型编辑，避免改变编号与关联。

“我的变化”使用明确版本编号关联，不按文字相似拼接变化。仅比较已确认内容的旧版与当前有效版本；忘记后的内容不展示。历史数据缺少版本关联时不推测补齐。认识修正不自动认定为个人成长。
