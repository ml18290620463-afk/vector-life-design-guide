# VECTOR 分身设计：基于经历、确认与持续校准

> 历史设计快照：文中的分类、实现状态和未完成项仅代表当时方案，不是当前功能清单或待办。当前职责、导航和数据关联以[模块数据归属与联动](data-linkage.md)及[当前范围](../ROADMAP.md)为准。

依据《录屏内容提取.md》完善。录屏中的对话、示例档案和用户偏好均为参考素材，不作为当前用户资料导入。

## 产品定位

分身基于本人留下的经历、已确认的理解、原则和目标，帮助回看、判断和行动。相似度来自具体选择及其变化，而不是人格标签或模仿口头禅。它可以提出不同判断，但必须说明依据和不确定性。

## 六层结构

六层按职责分工，共享已有数据结构。身份回答“分身是谁”，档案回答“目前知道什么”，记忆保存“依据是什么”，行为决定“如何回应”，校准负责“如何改变理解”，应用把这些环节连接起来。任何一层都不能绕过本人确认写入个人事实。

### 1. 身份层：关系与称呼

分身与本人平等交流，帮助观察和判断，不能替本人作出承诺。分身的名字属于分身身份，不等于用户姓名；用户的表达风格也不能从示例人物继承。

取名流程为“提出称呼 → 可编辑候选 → 本人保存 → 后续身份回应读取”。新保存的规范取名条目使用稳定 ID `avatar-name`，更名时由记忆存储保留旧版本。兼容旧版以 experience 保存的规范取名记录；不把普通句子中提到的名字或推断条目作为称呼。多个有效称呼按确认时间选择最新值；同一时间出现不同称呼时请求重新确认。

验收：保存“小树”后再次询问姓名、刷新后询问，都回答“小树”；未确认、已拒绝、未来生效或过期的称呼不能用于当前身份。

### 2. 档案层：当前资料的汇总视图

档案应当从现有原则、愿景、目标和已确认记忆派生，不另建一套会相互冲突的事实库。每项资料须能回到原模块或记忆来源。经历是理解的依据，不能仅凭一次经历生成稳定人格标签。

当前实现提供跨模块的只读回应上下文，并非完整档案页。后续聚合页应展示资料内容、性质、适用情境、来源与最后确认时间；未知字段留空，存在冲突时并列呈现。资料修改应回到拥有该数据的模块，经该模块的明确确认更新。

验收：删除或停用相关依据后，后续回应不能继续当作当前依据；缺少职业、所在地等资料时不补全；录屏中的人物资料不进入用户档案。当前来源存在性检查覆盖日记引用，其他来源类型的完整生命周期联动仍需扩展。

### 3. 记忆层：主题、标签、性质与审核状态分开

`facets` 表示内容主题，`tags` 表示用户可见的组织标签，`nature` 表示内容性质，`status` 表示审核或生命周期。四者独立：确认一个推断，只代表本人认可这条理解，不代表客观证实；给记忆打上某个标签，只代表它被纳入该主题线索，不代表产生新的事实。

| 性质       | 适用内容                       | 回应约束                         |
| ---------- | ------------------------------ | -------------------------------- |
| explicit   | 本人明确提供的资料、偏好、观点 | 作为本人表达引用，不宣称外部核实 |
| experience | 已发生的具体经历               | 保留事件情境，不推导为长期特征   |
| commitment | 计划与承诺                     | 未取得完成证据前不能说已完成     |
| state      | 某时的情绪和感受               | 说“曾经”，不据此断言当前感受     |
| inferred   | 推断、含混或混合小结           | 保持待验证措辞，鼓励拆分核对     |

保存前展示性质选择框；关键词只提供保守建议，修改内容后重新建议，最终由本人核对。来源引用在生成候选时固定，后续无关聊天不会被错配为该候选的来源。目前小结引用的是参与生成的本人发言集合，尚未实现逐句证据对齐。

标签管理作为记忆系统的统领层：同一标签可以汇总来自记录、目标、原则、行动和陪聊的相关记忆，用于筛选、专题复盘、发现变化和建立跨模块关系。标签应短、稳定、可复用；可由本人选择、原始记录事件标签、目标/原则关联或模型保守建议产生。当前界面已支持标签总览、按标签筛选记忆、单条记忆标签编辑、标签重命名、合并、归档/恢复和别名记录；这些操作只改变组织方式，不静默改写记忆内容、性质、来源和审核状态。一个标签下若存在冲突记忆，应并列呈现并标注时间与来源。

时间字段须区分来源时间、创建时间、确认时间和有效区间。`validFrom` 包含起点，`validTo` 不包含终点；无时间边界表示未知，不表示永远成立。当前召回和生成回应前均检查有效区间，只接纳 confirmed / retained 原子记忆；历史状态只供后续变化回看使用。保存时的 confidence 是保守启发值，不是校准过的概率，更不是对用户的评分。

验收：混合小结默认待验证；手动选择的性质真实落库；标签随原子记忆保存并进入标签管理界面，可被查看、筛选、编辑、重命名、合并、归档和恢复；未来生效、过期、候选、拒绝、被替代条目均不进入当前原子记忆召回。

### 4. 行为层：先核对依据，再组织回应

一般陪聊先回应当前表达；涉及个人判断时引用相关依据，并保留其性质。推断说“仍需验证”，旧情绪说“曾记录”，计划说“是否完成需要核实”。没有相关依据时允许直接说不知道或提出一个必要追问，不以人格标签填补空白。

当前自然回应由本地意图识别和召回规则生成，关键词匹配存在语义边界。搜索、社交、发送消息和执行行动属于后续能力，不能在回复中声称已完成。复杂问题可以给出依据和下一步，但建议本身不能自动生成承诺或行动记录。

验收：同一偏好主题下，explicit 与 inferred 的表达不同；确认过的 state 也不能写成当前情绪；提到计划不能自动增加完成进度。

### 5. 校准层：区分纠错、变化与适用范围

校准应区分三种情况：原理解错误（修正内容）；本人发生变化（保留过去版本及截止时间）；只适用于某个场景（补充情境，不作全局覆盖）。每次聊天可产生候选，不要求每轮都弹出确认，认可回复或继续聊天也不等于保存。

当前已实现保存前编辑、性质核对、忽略候选和明确保存。同 ID 内容变化保留 superseded 历史；不同 ID 的冲突仍并存，尚无自动语义冲突处理。新取名采用稳定 ID，因此更名会走版本更新。对于其他记忆，完整的保存后纠错、范围调整和冲突比较界面仍需建设，不能声称已经自动解决矛盾。

验收：保存前清空内容不能提交；忽略不新增记忆；更名后旧称呼进入历史；自动提取不能覆盖已确认或已拒绝条目；写入失败保留候选并提示失败。

### 6. 应用层：连接会话、生成、审核与存储

主数据流为：本人消息 → 当前上下文与有效依据 → 回应 → 按需生成候选 → 编辑内容与性质 → 明确保存 → 更新后续召回。读取与写入分别执行，模型输出或本地规则输出都不能直接成为正式个人资料。

当前一般陪聊回应使用本地规则；陪聊小结会调用 `summarizeAvatarMessages` 的 `/api/v1/avatar/summarize` 接口，失败时使用本人发言生成回退小结。growth-preview 只生成候选。已有摘要接口不意味着通用陪聊模型、向量库或时间图谱已经接入。前端摘要仍需本人审核，引用本人发言也不保证摘要逐句无误。

存储沿用现有原子记忆结构与容量限制，保存成功后重读存储更新上下文。后续模型接入必须传递内容性质、来源、时间、审核状态，且把引用文档当作数据处理；外部服务不能绕过现有确认流程。

验收：断开摘要接口后仍能生成可核对的回退候选；保存失败不宣称成功；页面重载后已保存身份可被召回；移动端候选内容、性质选择与保存按钮可操作且没有横向溢出。

## 记忆分类与分级

分类沿用现有结构，避免建立第二套不兼容的存储：基础事实对应 domain_background；偏好对应 preference/aversion；价值观对应 value/boundary；目标计划对应 aspirational_self/commitment；习惯对应 habit/behavioral_pattern；经历对应 experience；关系对应 relationship_view；情绪对应 state/emotional_trigger。推断始终保留 inferred 性质，即使本人认可，也不是客观验证的事实。

在分类之上增加标签管理项。分类回答“这条记忆是什么类型”，标签回答“它归入哪些长期线索”。标签可以统领整个记忆系统：例如“职业发展”下同时出现经历、偏好、边界、目标和行动；“分身产品”下同时连接想法、计划、反馈和决策。标签不应被当作人格标签，也不能用标签频次自动生成价值判断。

临时上下文留在会话和提取预览里。高置信度不等于长期价值：一次性情绪、假设、玩笑不因分数高就进入长期候选。具体、稳定、可复用的表达才提议保存；用户也可主动保存重要经历。

候选必须可追溯到本人发言或本人记录。助手和系统发言不得成为个人经历的证据。来源时间和提取时间有不同含义；未知来源时间不伪造为真实发生时间。

## 写入与更新

1. 提取只产生 candidate，不因聊天、点赞或模型自信而确认。
2. 保存前展示可编辑内容、来源、记录时间和未保存状态；正式写入由明确的保存动作触发。
3. 对已审核条目的再次自动提取不能降级或覆盖它，包括已拒绝条目。
4. 同 ID 内容改变时保留旧版本及有效截止时间；不同 ID 的冲突候选并存，不能自行决定谁正确。
5. 当前本地存储最多保留 400 条原子记忆，历史版本也计入容量；这不是无限历史档案。
6. 原则、目标等由用户在对应模块主动修改时，同步投影遵循原模块的确认操作；不将这种投影视为聊天自动写入。
7. 保存失败必须返回失败，不输出“已保存”。删除与来源解绑沿用既有模块机制。

## 十二部分行为规范与模型提示词

完整规则集中在 [VECTOR 分身行为规范](./avatar-behavior-spec.md)，包含身份、核心目标、事实边界、记忆分类、写入、更新、对话行为、个性化表达、输出格式、候选格式、禁止事项与校准机制。本文件保留架构职责与验收条件，避免维护两份相互漂移的提示词。

后续通用对话模型接入时，以行为规范为基础注入实际可用能力，再提供带来源、性质、时间与状态的用户资料。当前本地规则不会自动执行 Markdown 规范；摘要接口也不等同于通用对话模型已经接入。

## 后续边界

完整的独立档案编辑页、逐条候选管理与冲突比较界面，以及完整的模型语义提取与通用陪聊，仍是后续工作。本次已把现有陪聊保存、候选提取、历史保留、事实措辞和记忆标签管理闭环补齐；本地关键词规则无法可靠识别所有反讽、引用与复杂否定，仍需本人审核。
