# 资料库检索性能基线（2026-10-09）

此基线只覆盖「过去」模块的确定性筛选。它的目的，是保证资料规模增长后仍能找回用户已保存的事实；不以模型语义检索替代日期、标签和已存关联。

## 范围与预算

| 用户可见操作         |                                    数据规模 |                                                                        预算 | 验收方式                     |
| -------------------- | ------------------------------------------: | --------------------------------------------------------------------------: | ---------------------------- |
| 日期和标签筛选       |                       1,000 / 10,000 条记录 |                                        10,000 条的纯计算中位数不超过 100 ms | `npm run bench:past-search`  |
| 按关联行动或原则筛选 | 10,000 条记录、10,000 条行动、10,000 条原则 |                                       关系索引加单次筛选中位数不超过 150 ms | 同上                         |
| 呈现筛选结果         |                                  任意结果集 | 初次屏幕最多呈现 100 个记录卡；用户可按批加载更多，完整命中数与全选语义不变 | 组件测试与浏览器端验收       |
| 内存                 |           10,000 条文本记录（不含导入媒体） |                                不复制记录正文；只保留 ID 集合和当前筛选结果 | 代码审查与浏览器 Memory 面板 |

性能数值是产品预算，不把本机毫秒值作为 CI 的硬失败条件，避免不同 CPU、节能模式或共享执行器造成偶发失败。确定性筛选语义由 `features/mobile/pastSearch.test.ts` 固定。

## 测量方法

运行：

```bash
npm run bench:past-search
```

脚本在 Node 中生成 1,000 和 10,000 条合成经历，并为每个场景预热 3 次、测量 15 次、报告中位数：

1. 日期加标签；
2. 关联行动；
3. 关联原则。

关联资料采用一次性 `Set<entryId>` 索引。筛选循环只进行集合查询，避免每条记录反复扫描全部行动或原则。索引本身也单独报告，因此能判断是关系资料增长还是记录扫描导致退化。

## 2026-10-09 本机结果与决策

在本仓库开发机（2026-10-09）执行 `npm run bench:past-search` 的中位数如下（毫秒）：

| 记录数 | 场景       | 建立关系索引 | 筛选 |
| -----: | ---------- | -----------: | ---: |
|  1,000 | 日期和标签 |         0.09 | 0.09 |
|  1,000 | 关联行动   |         0.09 | 0.10 |
|  1,000 | 关联原则   |         0.10 | 0.10 |
| 10,000 | 日期和标签 |         1.06 | 0.16 |
| 10,000 | 关联行动   |         0.91 | 0.39 |
| 10,000 | 关联原则   |         0.94 | 0.37 |

该测量不代表低端设备；发布前仍需在目标浏览器和低端设备抽样。

当前代码已消除关系筛选的二次扫描，纯筛选满足预算时，不引入持久化全文索引：它会增加加密数据同步、删除和恢复的一致性负担，却不提升确定性召回。

时间线初始只创建 100 个记录卡；用户可按批加载更多。搜索、关联来源、全选删除和“显示 N 条”始终基于完整命中集，所以逐段呈现不会改变召回或批量删除范围。当前批量加载已满足渲染预算，无需引入虚拟列表；如果实际设备上每批渲染仍影响滚动，再以相同语义替换为 `@tanstack/react-virtual`。

## 边界

- 基线不测媒体解码、备份、数据库读取、浏览器冷启动或网络；它们不属于纯筛选函数。
- `data:` 媒体会显著改变存储和内存曲线，另由素材引用韧性项处理。
- 资料超过 10,000 条或任一场景超预算时，先保留确定性筛选语义，再评估增量索引与虚拟列表。
