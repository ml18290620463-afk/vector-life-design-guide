# VECTOR 五批次工程交付与后续验收（2026-10-07）

## 范围与状态

本轮按「行为标准、评测基线与恢复保障 → 资料使用 → 处境分析 → 理解更新 → 结果反馈」落实工程能力。分身的目标是帮助用户看清当下处境、探索成因和现实限制、比较更好的选择；历史经历提供可修正的参考，不默认沿用过往习惯。

这是工程交付记录，不是模型质量成绩或产品价值评分。第五批已完成结果进入后续分析的工程连接；真实体验验证仍待开展。本轮代码保存在独立工作树，未更新用户正在访问的 3010 服务，也未部署或推送。

## 第一批恢复保障的具体范围

受密码保护的资料库导出带认证头的 AES-256-GCM 文件，密钥使用 PBKDF2-SHA256、600,000 次迭代、独立盐和 IV。文件包括记录、原则、行动、未来目标与结果、草稿和分身缓存；不包含用于替换本机登录凭证的密码哈希。

恢复前校验版本、密码、文件完整性、记录与关联。跨密码导入按目标资料库密码重新保护内容，保留目标密码。空资料库恢复会建立密码保护。合并时同编号不同内容拒绝写入，草稿冲突拒绝合并；重复恢复相同备份不重复创建数据。

主要数据写入有事务及会话状态检查。旧式本地缓存恢复失败时，保留持久恢复任务；受保护资料库的恢复任务加密保存，解锁后再重试。恢复密码弹窗支持焦点约束、Escape、焦点恢复和卸载取消。

单元测试覆盖文件损坏和认证头变化、版本不支持、错误密码、空资料库、不同目标密码、重复恢复、编号冲突、缓存失败后解锁恢复等。浏览器测试实际导出文件，再通过上传入口取消、输入错误密码、正确恢复并重复导入，核对加密记录正文、草稿、目标、行动、分身记忆、目标密码和恢复任务清理。

## 当前边界

1. 行为标准是模型执行要求；结构测试和 mock 路由测试不能证明真实模型始终遵守。
2. 资料检索仍使用中文字对匹配及显式关联，最多选择 4 个相关来源，另带最多 2 条称呼记忆。原文参考每项最多 3 段、每段 700 字。不是完整的语义检索，未证明所有相关经历都能被找到。
3. 防止被拒绝理解重新写入依赖 ID、规范化文本及模式键；尚无覆盖所有同义表达的纠正分类器。
4. 历史结果是用户报告的情境反馈，不证明因果，不等于成功概率。
5. 本轮保护了导出的备份文件与恢复任务；分身记忆和聊天等旧式 localStorage 缓存仍是本地明文。不能宣称全部本地资料均已加密。
6. 浏览器恢复验证使用真实入门解锁会话和已有 SPA 路由到设置所在的 Dashboard；未新增设置导航入口，未改动现有首页布局。

## 接下来按门禁推进

### 下一步：实际模型评测

按 [分身行为与评测基线](./avatar-evaluation-baseline-2026-10-07.md) 运行开发集的「有历史资料 / 仅当前会话」对照，用同一模型配置、两名评审独立盲评；调整后再运行未参与调试的保留集。记录归属、时间、处境理解、选择价值、连续性与纠正、依据边界、交互负担及原句证据。

严重边界错误目标为零；资料相关性至少 85%、指代连续性至少 90% 是待验证的验收目标，不是已有成绩。保留集失败例若进入调试，需要补充新保留场景。没有历史的对照若同样好或更好，优先修复资料选择及使用方式。

### 再下一步：小规模任务体验

邀请 6–8 名用户自愿使用真实困扰完成「说清处境 → 对照历史 → 纠正理解 → 比较选择」任务。记录哪些具体信息增加了理解、哪个选项原先未被考虑、哪些判断不适用、哪里让人感觉被定型或打断。先修复明确误解和交互障碍。

### 后续：2–4 周自愿试用

观察现实条件变化后，分身能否更新理解；用户是否采用、调整或放弃建议；结果是否支持更清楚的下一次判断。不要把消息数、记录数或留存单独作为实用价值证据。持续迭代顺序为严重误判与资料安全 → 相关性与纠正 → 选择质量 → 反馈负担与界面细节。

本地明文缓存的保护也应进入下一阶段工程计划：迁移到受资料库密码保护的存储，并验收锁定、解锁、迁移失败及会话恢复。其优先级由实际发布范围和资料敏感度决定，不应以备份加密替代本地保护。
