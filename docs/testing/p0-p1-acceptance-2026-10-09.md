# P0 / P1 实施与验收记录

日期：2026-10-09。实施起点：`692007c`。本记录区分工程实现、自动验收和真实使用效果。

## P0：备份恢复

已修复导入后普通加密记录在过去、搜索及分身资料入口仍被当作密文读取的问题。新增仅存在于解锁会话的读取模型，原始密文不被回写；锁定或更换密码时立即隐藏旧明文，私密与未到期封存记录不进入普通读取模型。打开原始记录仍走原有保护流程。

备份入口常驻分身页面的“数据与备份”；首次设置明确说明恢复凭证不等于内容备份。

验收覆盖：

- 全域往返：记录、嵌入附件和素材、原则与关联、引导星、容器、分身记忆与关系、标签、理解、会话、自定义锚点、草稿，以及愿景、目标、修订、行动、践行历史、成果与归档资料。
- 使用不同目标密码导入，保留目标密码；重复导入幂等；草稿冲突合并拒绝，明确替换才覆盖。
- 错误密码、密文损坏、版本或条目冲突不写入；缓存失败保留加密恢复作业，解锁后可重试。
- 浏览器真实导出文件 → 全新浏览器上下文 → 新密码资料库导入 → 搜索恢复正文 → 刷新 → 用目标密码解锁后再次读取。

范围边界：全域完整性通过代表性数据夹具验证，浏览器覆盖关键记录恢复流程。嵌入附件可随文件往返；外部媒体链接不等于离线媒体备份。文件加密不能推导为所有本地元数据或缓存均加密。单条普通记录解密失败目前会阻止读取并提示错误，未实现损坏条目的局部抢救。

## P0：真实模型评测

评测脚本支持通过本机忽略的 `--model-config` 文件传入用户自行选择的兼容模型服务、模型名和接口类型，与产品「模型接入」的自选模型机制一致。旧有 OpenRouter / Gemini 环境变量仅保留为本地兼容运行方式，不是用户或评测的前提。

本次执行 `npx tsx scripts/avatar-eval.ts --run` 时没有选择评测模型，返回 `model_not_configured`，仅生成 40 条开发集输入，模型调用数为 0，没有质量得分。真实模型评测未完成。用户选定模型并在本机提供其配置后，需执行开发集与独立留出集，按既有评测基线进行独立人工盲评，不能用合成数据生成或单元测试代替回答质量验收。

## P1：首次体验与最小闭环

- 空资料库或仅有示例记录时，“过去”提供“写下第一条记录”；首条真实记录保存后该提示消失。
- 编辑器提示只需写下发生的事和在意的一点，保存后可搜索找回，无须先选标签。
- 独立行动无须先建立目标或填写日期，即可记录真实进展。
- “调整后再做”必须填写具体的下一步；一次提交同时保存反馈和更新行动，旧反馈保留当时行动原文。
- 刷新后继续调整后的行动，完成后保留全部践行历史。分身的行动来源文本区分当时行动与调整后的行动，完成状态不自动代表有效性或目标进度。

首次体验与行动闭环代码已实施；真实用户首次任务成功率、耗时及后续价值仍需观察验证，尚未完成此前方案中的用户实验。

## P1.3 / P2：本地回顾、检索、素材与备份检查

本轮完成了不依赖模型配置的资料回顾与 P2 的三项资料能力增强。

- 资料库会基于已保存的经历、原则与行动生成“事实回顾”卡。卡片只列出最近记录、被这些记录支持的既有原则、相关行动和建立行动入口，明确标注内容不含模型推断。
- 资料库支持日期范围、标签、关联行动和关联原则筛选，并显示筛选后的结果数量。原有文本搜索和由原则、行动反查经历的能力仍可组合使用；10,000 条合成资料的确定性筛选正确性已有单元测试。
- 图片、音频、视频和链接素材可填写最多 240 字的用户说明。说明会随记录保存、进入资料搜索和可读文本导出；系统不会从未说明的素材推断内容。
- 备份页面新增只读“检查备份”：明文备份校验结构；加密备份在未提供密码时只展示不敏感的信封元数据，在提供密码后验证解密后的内容和资料域统计。检查不调用恢复写入流程，并始终提示外部链接和媒体地址无法在此处验证可访问性。
