# VECTOR 手机优先网页应用：UI 重设计需求

日期：2026-09-23。用途：设计交付与后续开发依据；本文件不代表功能已经实现。

需求依据：用户已确认的产品边界，以及现有模块与分类代码的抽查。本次没有进行全产品验收或外部竞品实测。标为“建议”的内容是待设计验证的新方案。

## 1. 产品定义与设计目标

VECTOR 帮助用户通过记录经历、回看选择、沉淀原则、规划并检验行动，更深入理解自己，改善下一次决策。

核心循环：记录经历 → 回看与沉淀 → 设计行动 → 践行并记录实际结果 → 更新对自己的理解。

交付形态：建议采用手机优先的网页应用，具备 PWA 安装能力，并提供独立构图的桌面布局。共享数据与业务逻辑；桌面不是放大的手机，手机不是缩小的桌面。

核心设计原则：结果优先、编辑按需打开、一份数据只有一个主记录、后台负责分类关联、用户控制结论确认。用户应知道当前在哪里、可以做什么、保存后发生什么、如何返回。

## 2. 信息架构与职责

| 模块 | 用户任务                                 | 一级内容                      | 不承担的展示                         |
| ---- | ---------------------------------------- | ----------------------------- | ------------------------------------ |
| 现在 | 记录刚刚发生的事、当时的感受与选择       | 记录入口、草稿恢复            | 历史记录总库、复杂分析仪表盘         |
| 过去 | 回看经历，保存反思后形成的原则           | 回看 / 沉淀                   | 新记录导航、未来计划管理             |
| 未来 | 设计愿景、目标、行动，并记录行动实际情况 | 设计 / 践行                   | 分身人格分类、目标与愿景的重复反馈表 |
| 分身 | 对话，并从多个维度理解自己               | 对话 / 记忆档案；设置独立入口 | 重复的经历库、原则库、愿景与目标列表 |

原则在“过去→沉淀”维护；模式在“分身→我的模式”展示；行动规划在“未来→设计”维护；行动实际结果在“未来→践行”记录。

同一条经历在不同场景中可以引用，但不能生成独立副本。同一条行动的规划与实际情况关联到同一行动 ID。过去可回看践行形成的经历，分身可引用它形成认识，无需用户再次填写。

后台实体或兼容旧数据使用的分类，不能直接成为前台全部菜单。删除旧入口不等于删除用户数据，迁移要保留原记录、关联与修改历史。

## 3. 手机端页面需求

### 3.1 全局框架

- 底部固定四个入口：过去 / 现在 / 未来 / 分身，图标配文字。
- 顶部仅保留当前页面、必要操作；不放大幅品牌标题、口号和操作原理说明。
- 页面以单列为主；避免卡片套卡片和多层横向标签。
- 建议首次使用进入“现在”；后续是否恢复上次位置由可用性测试决定。
- 主页面保留底部导航；独立编辑页隐藏底部导航，提供明确返回与保存。
- 返回优先恢复原列表位置、搜索条件与当前分类，不把用户送回模块首页。

### 3.2 现在：低门槛记录

默认显示一个清晰的“记录此刻”入口或输入区，有草稿时提供恢复入口。

记录正文是核心输入；日期默认当前时间，允许修改。心情与标签可选，选择后显示实际标签，不显示具有必填暗示的“0/2”。不要求用户先选完整分类再输入。

长记录使用独立编辑页。保存成功给出简短确认和查看入口；保存失败保留全部输入。退出未保存内容提供“保存草稿 / 放弃 / 继续编辑”按钮。

### 3.3 过去：回看 / 沉淀

回看：按时间显示记录摘要；搜索为直接入口，筛选收纳到一个按钮。点记录看详情，编辑与删除放在详情或管理菜单。进入批量管理必须显示选框、已选数量、删除及取消按钮。

沉淀：显示原则内容，新增与编辑使用小入口，不常驻编辑表单。原则需要明确保存按钮；用户不必先查模式再查经历才能阅读原则。依据可以在有需要时查看，不强制铺在首页。

空状态只说明当前没有内容，并给一个适当操作，不堆放教学卡片。

### 3.4 未来：设计 / 践行

设计页：依次显示愿景、目标、行动，每部分默认展示一条摘要及记录数，点击查看全部。行动展示的是规划，不是行动实际结果。

摘要优先呈现“要做什么、何时完成”，原因等信息仅在已有且有帮助时呈现；没有时间、原因或衡量指标时不补造内容。

使用一个统一编辑入口，在编辑器内部选择愿景 / 目标 / 行动。编辑已有条目时自动带入类型。正文优先；时间、上级关联等通过选择器填写，低频字段折叠。重复愿景先询问是否继续原愿景，不静默新增副本。

践行页：只保留“践行记录”一个主题，待检视数量以紧凑入口融入其中；下面显示已经保存的行动实际情况。待检视列表与已保存记录是不同状态，不用同一个编辑器中的状态选项切换二者。

点击待检视行动进入独立的行动记录编辑器：显示对应行动规划、选择实际状态、简述实际情况；下一步仅在延期或调整等需要时出现。具体状态值在实现时与现有数据模型统一，不新增另一套状态。

到期行动自动成为待检视对象，但不强制切换页面、不自动判定完成。愿景与目标不要求填写独立反馈；完成行动也不能自动证明目标达成。

保存实际情况后，回到践行记录并显示结果。若需要修改行动内容或目标，转到设计编辑器，并保留返回路径。

### 3.5 分身：对话与自我理解

对话与记忆档案是独立工作区，设置使用小入口，不全部嵌入聊天框。

记忆档案固定为“关于我 / 我的模式 / 我的变化”，内部维度使用抽屉式单列卡片：每行一张，摘要与数量清楚，展开后阅读内容。

建议内部维度如下，需以实际有证据的数据生成，避免预先铺满空抽屉：

| 分类     | 内容范围                                       | 呈现要求                                               |
| -------- | ---------------------------------------------- | ------------------------------------------------------ |
| 关于我   | 基础信息、重视的事、偏好与边界                 | 用户可确认、修正、删除；临时状态不直接固化为长期特征   |
| 我的模式 | 理解与判断、选择与行动、情绪与关系中的反复表现 | 描述适用情境，避免单次经历直接变成人格定论             |
| 我的变化 | 有证据的认识变化、选择变化与行动变化           | 显示时间范围与具体前后差异；证据不足时不制造“成长”结论 |

记忆确认保存的是从聊天中提取的个人信息，不是整段对话。例如“你更喜欢提前安排独处时间，是否记住？”提供确认、修改、暂不保存。

建议仅在发现新的、值得长期保留的信息或与旧记忆冲突时提示，合并同轮候选信息，避免每句话都弹窗。未经确认的推断不作为已确认事实使用。

分身可以依据经历、原则、计划与践行结果帮助判断，但不重复陈列其他模块的整套数据。后台持续整理和关联，前台不显示“分身整理”“开始汇总”等流程按钮。

## 4. 弹层与编辑规范

| 场景                     | 手机端建议           | 理由                               |
| ------------------------ | -------------------- | ---------------------------------- |
| 状态、日期、分类等短选择 | 底部面板或系统选择器 | 操作靠近手指，不挤占主页面         |
| 长正文、规划、践行内容   | 独立编辑页           | 给键盘与内容足够空间，返回路径清楚 |
| 删除、放弃、记忆确认     | 简短确认弹窗         | 明确后果，不承载复杂表单           |
| 记录详情与全部列表       | 独立详情或列表页     | 可深链接、可返回，避免层层弹窗     |

一个时刻只打开一层编辑界面。关闭、返回、浏览器返回均须处理未保存输入。保存中阻止重复提交；失败保留内容；成功明确反映到结果列表。

小图标不等于小点击区域：可见图标约 20–24px，触控区域至少 44×44px，主要按钮建议 48px 高。图标按钮须有可访问名称。

## 5. 桌面与手机如何区分

| 方面     | 手机                     | 桌面                               |
| -------- | ------------------------ | ---------------------------------- |
| 全局导航 | 底部四入口               | 左侧固定导航                       |
| 内容构图 | 单列，逐页进入           | 列表与详情并排、按任务分配空间     |
| 编辑     | 独立全屏编辑页           | 较宽的编辑面板或工作区             |
| 分身     | 对话与档案按页切换       | 对话和按需打开的档案侧栏           |
| 宽度     | 内容适配屏幕，不横向溢出 | 工作区充分用宽，长文字保留舒适行宽 |

建议以 390px 手机稿和 1440px 桌面稿为主稿，覆盖 360、430、768、1024px 的适配规则。不要给所有页面统一固定高度、最大宽度或强制双列；尤其避免内容很少却留下大块空容器。

## 6. 视觉方向

延续用户要求的深色基调，取消大片纯白内框；建议使用低饱和深绿灰背景，稍亮一级的内容表面和清楚的文字层级。具体色值在设计稿阶段验证，不直接照搬通用主题。

- 中文使用系统无衬线字体；正文及输入约 16px，辅助文字 13–14px，页面标题 20–24px。
- 以 4/8px 为基础间距，手机左右留白 16–20px；卡片圆角建议 12–16px。
- 普通文字对比度至少 4.5:1；状态不能只靠颜色区分。
- 通过留白、细分隔线与字号建立层级，减少阴影、渐变、装饰性边框。
- 输入、选框、保存、删除与返回状态使用统一组件；桌面有键盘焦点，移动端处理安全区、软键盘与字号放大。

## 7. 网页应用必须补齐的状态设计

以下是设计与技术验收需求，不代表当前均已具备：

- 网络离线时可明确知道草稿是否保存在本机；“本机已保存”与“已同步”必须区分，未实现同步不能显示已同步。
- 页面刷新、切后台、应用更新时保护未保存输入；安装引导与更新提示不打断正在编辑。
- 公共 HTTPS 地址可直接访问；localhost 链接只适用于运行服务的电脑，不能作为手机交付链接。
- 模型设置优先选择服务商和模型，支持自定义，能推断的地址不要求填写；API key 提供记住选择。
- 错误提示区分网络、密钥、额度与模型不可用，给一个明确下一步。不能把会员订阅等同于 API 额度。
- API 不可用时仍能查看已有数据和使用不依赖模型的记录功能。
- 提供清楚的数据导出、恢复与记忆删除入口；跨设备访问需要明确账户、同步与冲突策略。
- 密钥存储、代理服务、个人数据访问权限必须在技术方案中明确，不能仅靠“记住”按钮承诺安全。

## 8. 设计交付清单与验收

手机完整主路径：现在首页与记录编辑；过去回看、搜索筛选、详情、批量管理、沉淀与原则编辑；未来设计、分类全部列表、统一编辑、践行、待检视与行动记录编辑；分身对话、记忆确认、三类档案、抽屉详情与修正；模型设置及数据设置。

每个关键页面必须包含正常、有数据、空、加载、失败状态；编辑器额外包含键盘弹出、未保存返回、保存中与保存失败状态。桌面交付对应完整功能，不能只做四张首页效果图。

优先级：先完成四模块主流程和数据归属，再完成手机交互原型，再设计桌面构图与组件规范，最后实现并用模拟输入验收。语音、通知、桌面小组件、复杂动画等先不进入此次核心范围。

验收任务：

1. 新用户可以不理解分类规则就完成第一条记录。
2. 回看、编辑、删除记录后能明确看到结果并返回原位置。
3. 原则填写后有清晰保存入口，不强迫查询多层依据。
4. 愿景、目标、行动共用统一编辑入口，首页没有常驻复杂表单。
5. 到期行动可从待检视进入记录，保存后出现在践行记录；规划与实际结果不混淆。
6. 分身只确认提炼出的信息，不把聊天原文误存为个人事实；修正能反映到后续使用中。
7. 同一内容在多个场景使用时可追溯到主记录，不出现两份独立编辑数据。
8. 360px 宽度无横向溢出；键盘不遮住当前输入和保存；放大字体仍可完成操作。
9. 桌面充分利用空间，手机没有桌面式密集表格和多栏缩小界面。
10. 用公共链接在真实手机访问，验证刷新、返回、离线草稿、安装及错误恢复，而不只查看静态设计图。

## 9. 可交给 UI 设计师的简版任务

为 VECTOR 设计一套手机优先、支持桌面的个人成长网页应用。核心模块为过去、现在、未来、分身；现在记录，过去回看与沉淀，未来设计与践行，分身提供对话和关于我、我的模式、我的变化。界面深色、克制、结果优先；复杂输入按需进入独立编辑器，分类与关联留在后台。手机采用底部导航和单列层级，桌面采用左侧导航和适合任务的宽工作区，两端共享业务但独立构图。交付完整流程、交互状态、组件规范和可点击原型，不只首页。详细约束以上述需求为准。
