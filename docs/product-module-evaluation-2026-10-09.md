# Vector 功能模块价值评估与优化方案

原始评估日期：2026-10-09，评估基线 `9ad03e7`。以下评分与原始测试记录保留为改造前快照，不代表最新验收状态。

后续已实施备份恢复读取修复、全域备份往返测试、首次记录入口和行动调整闭环；当前工程验收、模型评测阻塞与用户验证边界见 [P0/P1 验收记录](testing/p0-p1-acceptance-2026-10-09.md)。真实模型与真实用户验证尚未完成，不能将 P0/P1 整体标记为全部完成。

## 结论

Vector 已具备「记录经历 → 回看证据 → 沉淀可修订原则 → 设计行动 → 记录结果 → 再次理解」的产品结构。当前最有价值的方向，是帮助用户把个人经历用于下一次现实选择。记录、搜索是基础价值；原则修订与行动结果反馈是差异化来源；分身能否稳定利用它们，仍需真实模型和用户实验验证。

现阶段适合小规模、带观察的真实用户试用。尚不足以仅凭功能数量或工程测试，断言产品已证明长期成长价值或付费价值。下一阶段优先顺序：修复影响信任的边界 → 降低首次价值门槛 → 验证闭环收益 → 根据收益扩展能力。

## 方法与证据边界

使用代码审查、针对性函数复现、类型检查及自动化测试。交互评估参考 ui-ux-pro-max 的可发现性、渐进披露、错误恢复与导航规则；不是完整视觉审计或无障碍认证。

评分为当前交付价值的专家判断，非用户满意度、模型正确率或商业成功率。每维 0–10 分：0–3 缺失或严重受阻；4–6 部分可用、仍有明显障碍；7–8 核心价值与实现有依据；9–10 需较强的稳定交付和实际使用证据。任务价值、差异化可评价潜力，可靠性和验证程度必须单独看。

权重：任务价值 25%、易用性 20%、可靠性 20%、闭环价值 15%、差异化 10%、验证程度 10%。易用性越高意味着操作负担越低。综合分为加权后换算百分制并四舍五入，约 ±5 分，不应用一两分的差别决定资源分配。模块相互重叠，因此不再平均成一个貌似精确的产品总分。

## 模块分析

### 现在：稳定保留经历，比增加输入形式更重要

已实现文字、心情/事件标签、图片/视频/链接素材，以及草稿恢复。标签非强制，有利于低负担记录。直接价值是把当下经历可靠保存，并为以后找回提供线索。

应保留轻量入口，优先优化保存反馈、恢复可见性和从回看返回时的连续性。暂不以新增录音、更多情绪分类作为首要投入。

素材能力需准确表达：`nowRules.ts` 将素材类型和标题写入记录正文，并单独保存 `nowMaterials`；已检查的分身来源构造以文本为主。不能由“可上传图片或视频”推导出“分身已理解素材内容”。若扩展多模态，应先测试用户是否真的需要从素材提取信息，再增加可确认的提取结果。

### 过去：让用户找回有用证据，而非仅浏览时间线

回看、搜索、批量选择删除、原则维护已有实现，能解决查找经历的直接任务。与普通日记的区别，取决于用户能否找到支持或反驳当前判断的具体经历。

下一步验证自然语言任务，如“找出上次沟通有效的那条记录”，观察成功率和耗时。基于失败案例补充时间、标签或关联对象入口，避免一次增加大量筛选器。

### 原则与理解修订：值得重点保留的长期价值

`principleRevision.ts` 区分 correction 与 evolution；被替代的原则不再作为当前原则，演变历史可保留。这个设计允许承认旧理解有误，也允许理解随条件变化，优于把个人经验固化成永久标签。

风险主要在概念成本：记录、模式、原则、分身记忆可能被用户理解成四套需要维护的东西。建议把技术对象留在内部，在相关场景中表达为“发生了什么”“我目前怎么理解”“这次有什么不同”。不强制每条记录都沉淀原则。

验收应检查用户是否能说明一次修订的原因和适用条件，而不是统计新增原则数量。

### 未来：结果反馈比完成率更有产品价值

`actionPracticeSemantics.ts` 已将执行状态与效果分开，支持继续、调整、暂停、结束；已有独立行动、追加践行与目标关联。无需再次开发这些已有能力。

真正优势是：一次行动即使完成，也可能无效；未完成也可能暴露计划或环境问题。应减少用户从记录结果到更新理解的重复叙述，让相关经历、行动和原则自然带入，保留用户确认权。

下一步不是扩建任务管理器，而是测试一次最小闭环：记录一个困扰 → 选择一个小行动 → 说明实际结果 → 决定下次保留或调整什么。愿景与目标保持可选。

本轮浏览器测试暴露回归测试与界面不同步：3项用例仍等待“实际情况”，当前表单标签已是“实际发生了什么（可选）”。这是可确认的测试定位问题，不足以断言用户无法填写或数据丢失；但在修正定位并复跑前，也不能认为完整闭环已验收。因此下调验证程度与可靠性交付信心。

### 分身：最大机会，也是当前最大验证缺口

已有时间查询、确定性数量回答、文本与本地语义召回、来源过滤、记忆确认/修订机制。锁定或不可访问正文被过滤，操作类请求可走本地路径，这些是信任基础。

本轮复现两个边界问题：

1. **短追问丢失时间限制。** 合成两条同主题资料，分别发生于 2025 年与 2026 年。调用 `selectAvatarGuidanceContext`：首问“去年工作压力”仅返回旧资料，随后“继续”返回新旧两条。原因是范围只从最新消息解析，而主题另行继承。此结论限于上下文选择层，未声称观察到真实模型输出错误。
2. **单独年份未识别。** “2025年工作压力”也返回新旧两条；`parseAvatarTimeRange` 支持相对年、年月、日期和月区间，但缺少单独四位年份语法。应与短追问范围继承一起补齐。

建议显式维护可继承的会话范围，明确新范围覆盖、换主题清除、跨年比较例外，并让用户在需要时看到“本次依据：2025年”。不应简单把所有旧时间条件永久套用到新话题。

现有评测基线有 60 个单段、20 个多轮场景，40 个保留场景（50%）。文档明确：双人盲评及保留集质量验收尚未完成。85% 资料相关性和 90% 指代连续性是目标，不是已有成绩。应先用现有评测体系验证真实模型，不再仅增加提示词或 mock 测试。

### 数据保护：实现存在，可发现性和恢复演练需加强

完整备份及合并/替换恢复已有实现，覆盖记录、目标、分身档案和草稿；启用本地加密时导出也加密。不要将它重新列为缺失功能。

当前活跃分身路径通过“备份/恢复”等关键词打开功能卡片。用户需要知道可以这样请求，存在可发现性风险。建议增加稳定可见的“数据与备份”入口，展示导出时间并解释恢复凭证与资料备份的区别。不能把已设置密令或已保存恢复凭证等同于全部资料已有异地备份。

本地优先不等于所有 AI 在本机运行：配置的外部供应商会接收必要上下文。建议在首次启用分身时说明实际发送内容和可用的本地功能，不需要每轮弹窗。

### 首次激活：优先验证的体验瓶颈

现有首次路径包含创建密令、发放/保存恢复凭证；分身配置还涉及服务商、API Key 和模型。对普通用户，这些步骤可能先于可感知的产品收益。此处是基于流程的摩擦判断，尚无流失率数据。

建议先让用户通过已有记录/独立行动路径获得一次结果；AI 配置放在真正需要分身时，提供清晰默认选择和错误恢复。任何体验简化都不应绕过真实数据的保护要求。若引入体验演示，应使用明确标识的虚构资料。

## 实际价值如何测

建议试用阶段的核心观察指标为“得到具体帮助的回顾或选择次数”：用户能指出所依据的经历、得到的新理解或不同选择，之后还能核对行动结果。

配套观察：首次有用结果耗时、找回指定经历的成功率、错误引用/事实纠正次数、后半程自愿再用人数、完成一次回顾需要的操作与时间、备份恢复成功情况。只在知情同意下收集最少量事件或访谈记录，不默认上传日记正文。

选择6–8名存在真实反复困扰或自我回顾需求的用户，避免全部来自熟悉产品的开发者。先做无提示任务，再进行2–4周自愿使用；记录失败、弃用及“不如普通备忘录”的反馈。真实模型盲评与用户实验分别报告：前者证明行为质量，后者验证是否值得使用。
