# Stripe 付费前验收

更新：2026-11-23。状态：**未通过真实 Stripe 测试环境验收，不建议启用生产收款**。

当前新用户直接进入 NOW；没有必须先完成的新手引导。使用 `npm ci`、安全填写 `.env.local` 后运行 `npm run dev`。环境键以 `.env.example`、`services/stripeIds.ts`、`server.ts` 为准，测试密钥不得放进交付包、截图或日志。

## 已有证据及代码缺口

`server/stripeRoutes.test.ts` 使用模拟 Stripe client 验证参数、SKU、checkout 成功、签名拒绝、事件忽略、铸造与领取、缺失元数据等；授权存储与 token 测试验证签名、归属、到期和清除。这些都不代表真实支付通过。

当前 webhook 仅处理 `checkout.session.completed`；领取 token 只在进程内 Map 中保留约 30 分钟，领取后删除。没有持久化事件幂等/跨实例恢复；内部铸造失败仍返回 200，会阻止 Stripe 自动重试；未实现退款撤权和订阅续费/取消完整生命周期。离线签名 token 无法仅凭服务端退款即时失效，需要明确在线撤权校验或短期续期策略。上述是实现缺口，不是补几个密钥就能通过的验收。

## 先实施，再运行 sandbox

1. 引入持久化 entitlement/event/claim 存储；对 Stripe event ID 和业务 session 建唯一约束，事务提交后才确认 webhook。临时错误返回可重试状态，不打印密钥或付款人完整信息。
2. 明确付款状态/金额/货币/SKU 校验和异步支付成功/失败事件；只在满足履约条件后授予权益。绑定账号或可靠安装归属，领取可安全重试。
3. 实现订阅续费、取消、到期、退款/争议与撤权策略；设计离线有效期、宽限期和恢复流程，再补乱序/重复/并发事件测试。
4. 实现重启、跨实例和换设备的授权恢复；提供脱敏审计记录与人工处理流程。
5. 使用 Stripe test mode、测试 Price ID 和测试签名密钥，监听本地 webhook 或测试部署；确认没有 live key。保存事件 ID/时间/结果和脱敏截图供复核。

| 场景 | 验收标准 | 当前状态 |
| --- | --- | --- |
| 支付成功 | 测试订单、签名事件、权益和客户端展示一致 | 仅模拟基础路径；sandbox 待测 |
| 取消、失败、异步失败 | 不授予付费权益，可重试且不重复扣款 | 生命周期待补齐及实测 |
| 重复、并发、乱序 webhook | 持久化去重，权益只变更一次且状态单调正确 | 实现待补齐 |
| 内部失败后 Stripe 重试 | 返回可重试状态，恢复后最终一次履约 | 当前有 200 吞错缺口 |
| 部分/全额退款、争议 | 根据公开政策改变权益；离线边界可解释 | 实现待补齐 |
| 续费、取消、到期 | 账单周期与授权期限一致 | 实现待补齐 |
| 重启/跨实例/已领取恢复 | 已付款者可恢复，其他账号不能领取 | 持久化恢复待补齐 |
| 伪造签名、错账号/安装、过期 token | 拒绝且不泄露 token | 有模拟/单测；sandbox 待复核 |

每个场景记录前置状态、测试事件、预期与实际结果、相关 ID、清理动作。全部通过后再决定是否启用真实收款。本文件替换旧版包含强制引导和过时启动命令的验收说明。
