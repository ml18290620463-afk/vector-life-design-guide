# VECTOR 账号隔离与加密同步接入记录

当前状态：代码与本机测试完成了基础实现，新 Supabase 项目的公开配置已写入本机 .env.local，认证设置接口连接成功。用户已执行数据库迁移，匿名读取、写入 RPC 及直接读表均实测被拒绝；真实双账号与跨设备验收尚未完成，不得据此宣称已支持生产环境多人安全使用或无缝跨设备同步。

## 身份与资料

邮箱验证码确认登录身份；Supabase user.id 是资料归属唯一标识。显示名称、资料库密码均不是账号标识。两位用户同名、同资料库密码也使用不同的本机数据库与云端归属。

资料库密码在浏览器内加密完整同步快照，云端保存 AES-256-GCM 密文。该密码不上传。邮箱验证码不能解密资料；遗失资料库密码仍可能无法恢复旧资料。安全边界不包含恶意浏览器扩展、同源脚本入侵或已被控制的设备。

旧版本地数据不会根据名字或密码自动归入账号。由本人从旧版本导出加密备份，再登录自己的账号导入。

## 接入配置

1. 确认 Supabase 项目和 VECTOR 部署地址，核查项目现有表，避免与已有业务冲突。
2. 在项目执行 `supabase/migrations/202611120001_account_vaults.sql`。此迁移创建新表与 RPC，不应重复执行。
3. 启用邮箱认证，邮件验证码模板包含 `{{ .Token }}`，生产环境配置可用邮件发送服务并核查频率限制。
4. 部署环境设置 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`（公开客户端密钥）及 `VITE_REQUIRE_ACCOUNT=true`。不得将 service_role 或数据库密码放入 VITE 环境变量。
5. 重新构建部署。使用 HTTPS；Web Locks 用于阻止同一账号同时在多个标签页写入。服务器 CSP 需要与构建使用相同的 Supabase URL。
6. 在真实服务完成下述验收后，才向多人开放。

## 必须完成的真实服务验收

- 两个不同邮箱账号使用相同显示名称和相同资料库密码，分别创建记录，互相不可见。
- 未登录调用读取与写入 RPC 均失败；账号 B 直接查询账号 A 的 owner_id 返回空；客户端直接插入、更新或删除云表失败。
- 两台设备登录同一账号，第一台写入后第二台能够解密恢复；错误密码及篡改密文必须失败。
- 两台设备从同一 revision 同时提交，只有一个成功，另一个得到冲突；历史版本保留。
- 请求中途锁定或退出不得将旧请求结果标记为已同步。
- 断网写入、恢复网络、密码修改、清理设备、旧版本导入均需验证。

## 当前行为与限制

每 15 秒及窗口获得焦点、恢复网络时检查同步。已解锁资料库可自动上传；其他设备的新版本当前需要点击“加载其他设备的更新”，输入资料库密码并重新打开。尚未实现无感拉取、逐条合并或多设备协同编辑。

冲突时可选择将本机设为最新版本或加载云端。加载云端前保存加密的本机恢复副本；恢复副本入口可以恢复或导出。恢复旧副本后仍可能需要该版本原本的资料库密码。导出的账号恢复副本与普通日记备份格式不同，当前尚无文件导入入口。

登录会话保存在标签页会话存储中。离线时已打开页面可继续使用，重新打开页面仍需联网验证登录。清除此设备资料不会删除云端历史；退出账号也不会删除本机加密资料。当前没有云端彻底删除入口。

每个加密快照上限约 20 MB，历史追加保存；上线前需要按实际用量配置容量监控、保留政策和服务端限流。当前实现不是面向无限历史或大型附件的存储方案。
