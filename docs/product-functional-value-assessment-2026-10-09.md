## 产品的实际价值

Vector 当前最有价值的能力不是替用户生成日记或给出人格判断，而是把一次经历变成以后可以查证、修订并用于下一步选择的个人资料。

已经可完成的最小闭环是：

```text
记录一件发生的事
  → 按文字、标签、原则或行动找回相关资料
  → 形成或修订一条暂时适用的原则
  → 创建一个可独立存在的小行动
  → 如实记录完成、部分完成、调整或结束
  → 带着结果回到资料和下一次行动
```

这个闭环的价值来自三项可验证的约束：原始记录仍可回看；原则可以被纠正或演变而非永久定性；行动的执行状态和效果不会被混为一谈。分身能够放大资料的可用性，但不应被当作闭环成立的前提。

## 评分方法

每项按 0–10 分评估。评分是工程与产品设计判断，不是市场成绩。

| 维度         | 含义                                                     |
| ------------ | -------------------------------------------------------- |
| 直接任务价值 | 不依赖其他模块时，是否解决清晰且实际的任务               |
| 闭环完整性   | 产出的信息是否能成为后续模块的输入并保留关联             |
| 判断可信度   | 是否保留原始证据、明确语义和可修订性                     |
| 操作确定性   | 在当前实现下，是否有确定的本地行为、错误恢复和自动化覆盖 |
| 认知负担     | 概念、配置与操作步骤是否会阻碍完成任务；分数越高负担越低 |
| 差异化潜力   | 相比普通日记、待办或聊天，已实现机制能否产生不同结果     |

综合分按直接任务价值 25%、闭环完整性 20%、判断可信度 20%、操作确定性 20%、认知负担 10%、差异化潜力 5% 加权。它用于排定工程投入，不代表产品整体“价值百分比”。

### 现在：低负担保存经历，价值明确

文字记录、可选标签、图片、视频和链接素材都可以保存；草稿可以在中断后恢复。当前输入说明明确“写下发生了什么，以及你在意的一点”，并说明标签并非前置条件。空资料库和只有示例资料时，“过去”会提供直达“写下第一条记录”的入口。

这使用户能够先保存事实，再决定是否整理。素材目前是证据附件和文本线索，不能解释为系统已识别图片或视频的内容；这一边界应继续保留。

记录保存后会提供会话内、可跳过的去向：继续记录、回看资料或建立行动。素材也可以补写用户自己的文字说明，说明随记录进入搜索和可读文本；系统不会把未说明的图片、音频或视频当作已理解的内容。

### 过去：已经能找回资料，尚未形成面向任务的检索

时间线按创建时间排序。搜索会匹配记录标题、正文与标签，也会将命中的原则和行动关联回相应记录；这比只搜索日记正文更接近“找回某次可用经验”。批量删除同时允许选择是否保留已沉淀的知识，并在删除后说明结果。

现有搜索的边界也很清楚：它以词面命中和既有关联为主，但已支持日期范围、标签及关联行动/原则的组合筛选，并说明结果数量。用户若以自然语言描述一个情境、只记得模糊时间或想比较两次经历，可能无法在确定性搜索中完成任务。分身中的语义召回不能替代资料库的可控检索，因为它依赖模型配置和上下文选择。

### 原则：把理解作为可修订结论，而不是永久标签

原则可由记录、模式和践行资料关联而来。修订明确区分“纠正旧理解”和“条件变化后的演变”；当前原则会排除已被有效后继版本替代的表述，演变的旧版本仍保留为历史背景。这保证了用户可以修正判断，同时不篡改原始经历。

这是产品从“存档”走向“经验可用”的核心能力。当前问题在于记录、模式、原则、分身记忆四类对象同时暴露时，用户需要理解它们的区别。未来界面应围绕事实、当前理解、下一次尝试来组织，而非要求用户维护四个知识库。

### 未来：行动结果已不再等同于完成率

愿景、目标和行动可以逐层设计，也可以跳过愿景、目标和日期直接建立独立行动。践行记录把执行状态和后续选择拆开：用户能记录完成、部分完成、未完成或调整；选择“调整后再做”时必须写明新的下一步；历史保留原行动，当前行动更新为新的下一步。完成后的结果还可以带入“过去”沉淀。

这避免了常见待办系统把勾选当成有效结果的错误。从记录、搜索结果和原则都可将可追溯的触发情境、依据与问题带入独立行动编辑器，行动也保留原资料关联。

### 分身：资料边界做得较好，价值受模型与可解释性限制

分身可读取经过访问限制过滤的记录、原则、行动、践行结果和确认的理解，且会构造来源、时间和证据。它支持时间范围解析、确定性记录计数、本地召回、理解确认与修订。用户可选择服务商、HTTPS 接口地址、API Key、模型名，以及 `chat` 或 `responses` 兼容接口；固定的 OpenRouter 或 Gemini Key 都不是产品前提。

分身有两类本质不同的能力：计数、来源过滤和规则回复是本地确定性能力；总结、比较、建议和语义理解取决于用户选择的外部模型。界面应把两者分开呈现，并让每个非确定性回答都能清楚显示“本次依据了哪些资料、哪些只是推断”。

没有配置模型时，资料库会生成确定性的“事实回顾”卡：仅呈现保存的记录、既有原则和相关行动，并可从最近记录建立行动。短追问的时间范围继承与单独年份解析仍需持续用真实模型评测验证。

### 连续性与数据保护：已具备完整恢复，需补局部故障处理

加密资料库可以导出认证加密的完整备份；恢复支持合并与替换，跨密码恢复会在目标资料库密码下重新加密。恢复后普通记录可以被“过去”、搜索和分身资料入口读取。草稿、未来数据、原则、理解、关系和缓存都纳入恢复范围；重复合并保持幂等，编号冲突、错误密码和损坏文件会在写入前失败。

这是高价值能力，因为产品的长期价值取决于资料资产仍然可用。当前恢复采取“任一普通记录无法解密就阻止读取”的整体保护策略，能避免悄然丢数据，却不能从少量坏条目中抢救其余资料。外部链接也不能被视为离线素材备份。

## 本轮实施状态

P0 的资料读取容错、恢复验收、分身依据与时间范围语义已经完成。P1 的行动交接、保存后的下一步和无模型事实回顾已经完成。P2 的确定性筛选、用户素材说明和备份只读检查已经完成。

备份检查会验证结构、版本、资料域统计和加密信封信息；它不写入当前资料库，也不验证外部链接或媒体地址仍可访问。恢复演练的隔离写入流程尚未实现，仍应作为单独的后续可靠性工作。

## 不应作为当前优化方向

复杂图谱、成长分数、强制打卡和更多人格标签不会直接补齐上述闭环，且会把可修订的经验判断重新固化为指标或分类。本轮不将它们纳入路线图。

## 建议的实施顺序

1. 先做 P0 的恢复局部抢救、时间范围语义和分身依据展示，保护资料并限定系统声称的能力。
2. 再完成 P1 的统一行动交接和无模型回顾卡，让核心闭环不依赖外部服务。
3. 最后按 P2 的规模基准决定检索、素材说明和演练工具的具体投入。

这样推进后，产品能在不配置模型的情况下完成“保存经历、找回证据、建立并复盘行动”；配置用户自选模型后，分身负责帮助检索、比较和表达，而不替代资料的真实性与用户的最终判断。
