# VECTOR 下一阶段优化方案与验收路径

日期：2026-10-07。评估基线：最新工作树 codex/home-ui-refinement，提交 075b2a5。
本文是下一阶段方案，不代表其中待建设能力已经上线，也不代表已经通过真实用户验证。

## 1. 产品目标

让所有经历服务当下，也服务可以重新审视的未来目标。

分身应帮助用户看清正在发生什么、区分事实与个人解释、探索困扰的可能原因、找到可以改变的条件、比较选择，并从实际结果中更新理解。过去的模式和原则只是有情境、可修订的依据；目标也可以暂停、改变或发生冲突。

“了解用户”不能退化为迎合既有认知；“成长”不能只等于增加记忆条数；“行动”不能只等于完成任务。有效的变化可能是重新理解问题、守住边界、调整环境、停止不合适的行动，或修改目标。

## 2. 当前最大的亮点及其边界

最大的亮点是个人经历、模式、原则、目标与行动已经有连接基础，并且允许用户确认、拒绝、修正和保留变化。

- 知识投影已经包含原则、愿景、目标、行动及其关联。
- 原子记忆已经有内容性质、审核状态、有效时间、历史版本及关系类型。
- 已有行动与结果反馈机制。
- 保存或主动提炼后的弹窗承担模式确认；分身可解释关联证据并提供纠正入口。
- 草稿保存、防重复提交及失败重试已经有工程回归。

价值假设：这些关联有机会让分身比孤立日记或无个人历史的聊天更了解具体处境。尚未证实的是它能否稳定提升真实用户的理解、决策质量、持续使用意愿或付费意愿。

## 3. 当前急需解决的问题

### A. 有关联结构，但当下分析没有充分使用

主对话检索使用最后一句用户表达，按词语重合选择资料并沿已有关系扩展；当前主模型资料以概括性陈述为主。相关原始经历片段、支持/反对结果及情境限制尚未系统地组合进入主分析请求。

风险：同词异义被混为同一问题；“那为什么”“这次呢”等追问丢失检索主题；只拿到概括，没有依据核对概括是否适合当下；已经完成的行动结果没有充分参与判断。

现有证据问答能读取关联记录，但这不等于主对话已经自动使用这些依据。

### B. 行为目标仍偏向下一步行动

现有模型规则已经包含盲点、动态地图、事实边界及时间差异，但仍强调把思考变成行动。需要更明确地处理外部环境、信息不足、关系互动、资源限制、目标冲突与替代解释。

风险：把困扰过早归因于用户惯性，或沿旧原则直接给建议；产生看似个性化但不适合当前处境的回应。

### C. 更新机制有基础，语义判断还不充分

已有历史版本、有效期及用户修订，但关键词冲突只能提示候选，不能可靠区分“过去理解错了”“用户真的改变了”“仅本次例外”“不同场景都成立”。

风险：旧标签反复回来，或把一次顺利/失败误当作长期变化。

### D. 加密资料库完整备份仍有缺口

当前完整备份在加密资料库下明确拒绝导出。草稿可靠性改善不能代替长期资料迁移与恢复。现有离线凭证也不是忘记密码后可解密数据的恢复密钥。

风险：用户越长期使用，浏览器清理、设备更换或本地损坏的代价越高。

### E. 工程验证尚未等于产品效果验证

现有报告记录 1,181 项单元测试，以及交互、布局、生产构建等检查；报告中的服务端健康检查未配置在线供应商，不能据此评价远程模型真实分析质量。也没有真实留存、理解改善或付费价值数据。

## 4. 用户界面约束

- 现在：轻量记录当下，不强制填写原因、模式或目标。
- 过去：回看、比较、主动提炼和调整理解。
- 分身：分析处境、联系历史、解释模式/原则、按需核对证据与纠正。
- 未来：维护可调整的目标和实践方向，不强制所有记录绑定目标。
- 模式认可、不认可与修正保留情境弹窗；关闭或 Escape 仅表示暂缓。
- 默认对话用自然语言说明与判断相关的理由，不常驻数据源列表、证据计数、可信度百分比。
- 用户询问“为什么这样理解”“哪些经历支持”时，才展开相关原文和结果。
- 不增加常态化分析表单或每轮必填反思任务。
- 建议不是承诺，对话中的认可不是自动写入长期记忆。

## 5. 五批次实施路径

### 第一批：统一分析标准，建立评测基线，同时补齐备份

产出：

1. 更新产品行为规范与实际服务端模型规则，使二者对齐最新目标。
2. 建立至少 60 个单段场景及 20 个多轮/跨会话场景；保留至少三分之一作为未参与调试的评测集。
3. 设计并实现完整加密备份与恢复。先明确内容范围、加密边界、密码/密钥责任和格式版本，再实现导入导出。
4. 明确本地规则与在线模型能力边界；模型未配置或调用失败时给出真实状态和可恢复操作。

评测覆盖：

- 他人经历、引用、否定、过去状态、计划与结果、反讽、一次例外。
- 用户自我变化、模式范围、原则失效、目标冲突、环境因素。
- 指代追问、纠正后继续、跨会话再次提及、删除/锁定资料。
- 没有足够历史时仍能分析当前事实，不编造个人依据。

备份验收：

- 经授权的记录、草稿、模式、原则、目标、行动、反馈及关联在干净浏览器中可恢复。
- 错误密码、损坏文件、版本不兼容、中断和重复恢复均不静默清空原资料。
- 对比对象 ID、正文、状态、版本与关联，核对恢复完整性。
- 文件不包含不应导出的凭据；加密方案不依赖明文导出中间文件。
- 密码遗失的能力边界用准确文案表达；不把校验凭证描述为解密密钥。

进入下一批的条件：评测基线可以重复运行；复杂场景有清晰正确/错误示例。备份可独立推进，但真实用户长期试用前必须通过恢复验证。

### 第二批：让分身找对资料，并承接上下文

产出：

1. 检索问题结合当前情境和最近有效话题，支持“那条”“为什么”“这次”。
2. 在已有数据结构上组织少量相关原始片段、已确认理解、例外、实际结果、当前目标与限制。
3. 保留来源时间、性质、审核状态和必要关联；避免在模型接口处丢失关键情境。
4. 排序兼顾场景相关性、当前有效性、证据质量和反例；不把频繁出现或最新出现等同于最可信。
5. 明确过往资料只是历史证据，被替代或撤回的理解不得被当成当前事实。原始历史事件可以在权限允许时用来理解变化。
6. 先比较当前规则检索与语义方案的实际差异，再决定是否引入向量检索。增加技术组件本身不构成产品改善。

建议验收门槛（项目目标，非当前成绩或统计保证）：

- 在预先标注且保留测试的场景中，至少 85% 的被选资料被复核为与当前问题相关。
- 指代/连续追问至少 90% 的场景保持正确讨论对象。
- 不将他人、锁定/已删除记录或撤回推断作为用户当前事实；严重边界错误在门禁集为零。
- 区分“找不到”“资料不适用”“缺少权限”，不补造证据。
- 记录回复延迟和请求体量，避免依赖加载全部历史换取效果。

### 第三批：打磨处境分析与选择比较

产出：

1. 回应当前问题，区分已知事实、用户解释和待确认判断。
2. 根据需要探索个人反应、关系互动、环境/资源限制和信息缺口；有依据时比较其他解释。
3. 对可行动的复杂问题，比较有实际差异的选择及条件、代价、可能结果。
4. 判断当前目标是否仍值得追求、是否冲突；不默认所有建议服从原目标。
5. 对关键未知只提出一个有用问题；信息够用就推进，不把分析变成问卷。
6. 简单问候、记录和情绪陪伴保持自然简短，复杂分析按需展开。

验收：

- 使用预先定义的人工评分表评估：准确回应、事实/解释区分、替代解释质量、环境因素、选择可行性、目标取舍、负担与语气。
- 严重编造个人事实、无依据确定动机、把旧模式当身份的场景不允许通过。
- 非必要时不强制输出两种原因或两条建议；不知道真实原因时明确只是待验证解释。
- 同样的困扰在目标、资源或环境不同的案例中，分析应体现差异。
- 和仅使用当前对话的基线做盲评，判断加入历史是否真的改善回答。允许历史无关时不用历史。

### 第四批：让新经历修正旧理解

产出：

1. 在现有版本机制上，支持明确错误、本人变化、范围差异、单次例外和未解决冲突的不同处理。
2. 用户说“那是以前”“只在工作中”“这次没发生”后，本轮立即调整，持久变更通过明确确认执行。
3. 保存/主动提炼时提出简短、可编辑的更新候选，避免每轮打断。
4. 用户拒绝或修订后，后续检索、生成和跨会话回应都遵循新状态。
5. 更新原则适用条件和例外，保留原始经历而非通过删掉反例保持结论。
6. 目标暂停、结束或变化后，不继续据旧目标施加行动压力。

验收：

- 跨会话测试“纠正→刷新→再问→补充不同场景”，旧错误不重新作为当前结论出现。
- 新证据不因时间更新就自动推翻旧证据；不同场景允许并存。
- 待确认候选不会悄悄成为已确认事实。
- 删除或保留来源的选择与之后可引用内容一致。
- confidence 保持内部排序意义，不输出正确概率或未经校准的确定性标签。

### 第五批：把实际结果转化为下一次判断依据，并开展用户验证

产出：

1. 在已有行动/结果反馈上补充低负担复盘，关注“什么发生了变化、哪个条件起作用、什么不适用”，而不只统计完成。
2. 结果通过明确关联影响后续理解；完成行动不自动等于原则有效，失败也不自动等于用户模式固定。
3. 用户无需每次复盘；在下次相关记录或主动回看时提供轻量入口。
4. 先让 6–8 名目标用户进行任务式体验，再进行 2–4 周自愿持续试用。样本用于发现问题，不能推导市场规模。

任务式研究：

- 不看说明完成记录、暂缓提炼、找回候选、修正模式、询问依据、修改目标。
- 检查用户是否理解“已保存”“待确认”“仅本轮调整”的区别。
- 检查弹窗时机是否自然、暂缓后是否找得到、对话是否过长或带来被评判感。

持续试用：

- 对话前后，用户能否具体说出新增理解或改变的选项。
- 建议是否因新结果而发生合理变化。
- 同类问题再出现时，用户是否发现更适合的应对。
- 非提醒驱动的主动回访、负担感、弃用原因及错误修正频率。
- 在明确同意范围内记录研究数据，不默认上传私人正文。

验收：工程门禁继续通过；产品继续/调整的依据来自具体任务表现、访谈及案例变化，不单看消息数或记录量。小样本前后比较不能证明产品带来因果性的长期行为改善。

## 6. 哪些可以立即完善，哪些需要用户数据

可立即完善：

- 备份完整性、错误恢复、模型请求边界、上下文召回和信息状态处理。
- 对话规则与产品目标一致性。
- 可纠正状态跨会话一致性，旧理解和当前状态的区分。
- 反例/例外的测试、来源权限约束、真实保存状态和降级提示。
- 明显重复、冗长的证据回答及功能入口含义。

需要真实用户数据：

- 用户是否愿意长期记录、哪些记录真的会在未来复用。
- 弹窗可接受频率和候选数量，主动提炼入口是否好找。
- 用户更常需要陪伴、分析还是比较选择，以及对话深度。
- 个性化分析是否优于一般对话，是否带来更好的现实判断。
- 长期回访、可持续价值、愿意付费的条件。

可先开展定性研究，不等全部智能能力完成；长期试用需要先具备数据恢复保障。

## 7. 推荐资源分配

第一优先：准确理解、上下文与相关依据、可纠正性，以及加密备份。
第二优先：结果反馈如何影响下一次判断，持续试用发现的交互负担。

## 8. 一条贯穿验收的示例

用户：“每次想推进自己的项目，都忙着接别人的需求，最后自己的事又没做。”

合格分析应：

- 先确认哪些需求是必须承担的，哪些可以协商；不直接宣布这是拖延或讨好。
- 按相关性参考过去的项目记录、曾有效的边界原则、此前行动结果和当前目标。
- 如果历史中在清晰交付边界下曾推进成功，把它作为范围条件，而不是忽略反例。
- 有依据时比较对拒绝的担忧、职责不清、任务定义不清或资源不足等解释，缺乏依据不认定原因。
- 结合现实比较重新协商范围、明确项目最小交付、保护投入时间等选择。
- 用户补充“这次是必须处理的紧急事情”后及时改变判断。
- 后续结果帮助检验条件；经用户确认，可以把笼统模式收窄为具体情境。
- 默认自然回应；用户询问依据时才展开具体历史记录。

核心效果：用户对处境的理解更准确，选择更有依据，新结果也能改变分身下一次的判断。

## 9. 执行顺序与真实用户数据依赖（补充）

先完成可以客观验收的工程能力，再用真实使用决定交互细节与价值取舍。前四批不以真实用户数据为前置条件；第五批拆为 5A 工程闭环和 5B 用户验证。工程实现完成不能表述为真实产品效果已经成立。

| 顺序 | 工程任务                                                           | 真实用户数据依赖                                         | 完成后交付                             |
| ---- | ------------------------------------------------------------------ | -------------------------------------------------------- | -------------------------------------- |
| 1    | 建立场景评测、统一实际模型规则、明确降级状态；同时推进加密完整备份 | 无。使用人工编写、虚构且不含真实私人资料的测试场景       | 可重复评测、行为示例、备份恢复验证记录 |
| 2    | 多轮检索、相关原文/反例/结果组装、状态与时间处理                   | 无。使用独立测试库验证检索；真实相关性偏好后续研究       | 可以连续追问并核对依据的分身版本       |
| 3    | 处境分析、替代解释、环境条件、选择与目标取舍                       | 无。需要实际配置的模型参与受控评测，不能只测接口或提示词 | 经保留评测集和人工复核的分析版本       |
| 4    | 错误/变化/范围/例外的分类与确认更新，跨会话遵循修正                | 无。用跨会话和状态转换场景验收                           | 新经历可修正旧理解的版本               |
| 5A   | 将已有结果反馈用于后续检索和判断，提供轻量复盘入口                 | 无。用成败结果不同的对照场景验证                         | 完整的记录—分析—实践—反馈—更新流程     |
| 5B   | 任务式体验与持续试用，确定下一轮修改                               | 有。实际用户参与，研究数据使用需明确同意                 | 观察记录、问题排序、继续/修改/暂缓清单 |

执行依赖：

- 场景评测和行为标准先于对检索、分析效果的评价。
- 第二批建立资料供给，第三批验证分析使用效果，第四批建立修正一致性，5A 验证结果如何改变下一次判断。
- 备份工作不必阻塞第二至第四批开发，但其恢复门禁必须在长期用户试用前通过。
- 第二批之后可以先开展小规模任务式可用性研究；这些观察不阻塞已经确定的准确性与可靠性修复。
- 未配置在线模型时，可继续完成检索、状态、界面和备份工程；在线分析质量验收保持未完成，不能用本地规则通过代替。

每批交付四项：

1. 当前预览中的可体验变化及代表场景。
2. 相应测试/人工评测结果，写明失败或未验证部分。
3. 尚存边界及后续依赖。
4. 下一批的明确范围；不重复重做已通过的低风险检查。

研究中的下一轮处理规则：

- 找不到入口、误解保存、丢失数据、编造事实、纠正不生效：先修复后再扩展试用。
- 弹窗过频、回答过长、复盘负担：提出具体交互调整，小范围复测。
- 历史没有额外帮助：先检查相关性、原文/反例供给与分析质量，不先扩增记忆量。
- 用户未行动：核对建议是否适合条件、目标是否仍有效；不直接推断意愿不足或产品无效。
- 使用少但关键场景有帮助：评估是否适合低频高价值定位，不只追求日活。
