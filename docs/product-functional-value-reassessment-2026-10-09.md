# Vector 功能价值复评与下一阶段优化建议

评估日期：2026-10-09。复评基线：`main` / `bbad4b3`（`feat: expose model evidence and failure boundaries`）。

本文只评估已经交付、可从代码和自动化验收中确认的功能价值。它不把真实用户满意度、留存、付费或外部模型回答质量当作既成事实；这些仍是需要单独验证的假设。早期快照见 [product-functional-value-assessment-2026-10-09.md](product-functional-value-assessment-2026-10-09.md)。

## 结论

Vector 的核心定位是可长期积累、随时调取的个人资料资源。用户可以记录、找回和重新理解经历，也可以独立规划未来；需要时才选择参考过去的经验或原则。保存经历本身就是完整任务，不要求立即转成行动。

现阶段最实际、也最有差异的价值是：**帮助用户把个人经历变成可核对、可修订、可按需调取的资料资产。** 这项价值不依赖把人归类为人格类型，不依赖成长分数，也不需要强制打卡。用户配置任意兼容模型后，分身可以帮助检索、比较和表达；模型不应代替事实、来源和最终判断。

现有功能支持资料、行动与结果之间的可选关联，但关联不是使用前提，形成闭环也不是产品的默认目标。损坏条目可被排除后导出为可恢复副本，恢复演练也不会写入当前资料库；素材备份边界和模型回答依据已直接呈现。唯一仍未跨过的质量门槛是：尚未以用户自行选择的真实模型完成独立开发集、留出集和人工盲评。因此，下一阶段的重点应转向真实模型评测与日常概念收敛，而不是再扩充功能对象。

## 历史评分与纠偏后的评估口径

2026-10-09 定位纠偏：下方分数保留为此前工程复评快照，不代表纠偏后的产品价值评分。原“闭环完整性”权重和“跨模块编排”得分偏重将经历转成行动，不能继续用于排序。后续复评应以独立任务价值、按需调取与复用、证据可信度、操作确定性、长期资料资产和用户自主性为维度；无关联的经历、原则和计划均是有效产物。不得把关联率或闭环完成率作为整体价值目标。

每项维度按 0–10 分评分，综合分按以下权重换算为 100 分。评分用于确定投入顺序，不是市场成绩，也不应以一两分差异作决策。

| 维度             | 权重 | 判断的问题                                       |
| ---------------- | ---: | ------------------------------------------------ |
| 直接任务价值     |  25% | 用户能否完成一个清晰、现实的任务？               |
| 闭环完整性       |  20% | 产物能否成为后续步骤的有据输入？                 |
| 证据与判断可信度 |  20% | 是否保留事实、来源、范围和可修订性？             |
| 操作确定性       |  20% | 本地行为、错误处理和自动化验收是否可靠？         |
| 长期资料资产     |  10% | 数据能否找回、迁移、恢复和长期再利用？           |
| 认知可控性       |   5% | 用户是否能理解当下该做什么，配置和概念是否克制？ |

“操作确定性”与“模型能力”刻意分开：本地检索、资料筛选和备份检查可以被确定性验证；总结、建议与语义理解要由用户自选模型的独立评测决定。

### 经历采集与素材证据：84 分

文本、可选标签与素材使用户能先保留事实，草稿恢复减少中断损失。素材说明由用户亲自补写，可进入搜索与可读文本，系统不擅自理解图片、音频或视频。素材界面和备份检查已经区分可移植的数据 URL 与仅保留地址的网页/本机引用，并为网页链接提供替换入口。这是可信资料入口；长期风险只剩下外部地址本身的可访问性，产品不会把它伪装成已保存的媒体本体。

### 资料找回、筛选与事实回顾：86 分

时间范围、标签、关联行动和关联原则筛选可以组合，10,000 条合成资料的筛选正确性、渐进渲染和性能基准已有测试；搜索还会沿既有关系找回资料。无模型事实回顾只列出记录、既有原则和相关行动，不生成未经证据支持的结论。这是当前最可靠的回看能力。短板从“能否找回”转为真实设备上的响应预算，以及不应越过确定性筛选边界的模糊情境表达。

### 原则与理解修订：83 分

原则不是人格结论，而是可追溯、可纠正、可演变的暂时理解；旧版本仍保留背景，当前版本不会混淆。它是产品区别于普通日记的关键。问题是日常界面仍会同时暴露记录、模式、原则和分身记忆等对象，用户需要额外学习它们的关系。

### 行动、实践与结果反馈：86 分

行动可独立创建，也可从记录、搜索结果或原则带入触发情境、依据和问题。实践记录区分完成、部分完成、未完成与调整，且“调整后再做”要求明确下一步。这使“完成率”不再冒充效果。实践结果现在可作为支持、部分支持或挑战原则的可回看证据；用户仍需主动确认原则修订，系统不从一次实践自动下结论。

### 分身与用户自选模型接入：75 分

分身会过滤不可访问资料，携带来源、时间和证据；用户可以选择兼容服务商、地址、密钥、模型与接口类型，不依赖固定的 `OPENROUTER_API_KEY` 或 `GEMINI_API_KEY`。每条模型辅助回复都展示收到的可核对资料数量、实际引用时间范围和“推断而非事实”的边界；无资料与请求失败也有明确的降级说明。计数、范围过滤和事实回顾是本地确定性能力；总结与建议仍依赖外部模型。真实模型尚未用带答案的资料集评估，配置和多个知识对象也提高了首次使用成本，因此它还不是产品信任的基础。

### 连续性：草稿、访问控制、备份恢复：88 分

全域加密备份已覆盖记录、未来数据、原则、理解、关系和缓存；合并幂等、跨密码恢复、错误密码和损坏文件的写前失败均有验收。只读检查能报告加密信封、版本、结构、各数据域数量和媒体可移植性，恢复演练不写当前库。一条无法解密的记录可被显式跳过，导出其余可读资料作为恢复副本，并报告跳过条目与受影响关联。这是个人资料资产的强底座。

### 跨模块编排：86 分

保存记录后的可跳过下一步、从记录/搜索/原则到行动编辑器的 `ActionDraftContext`，以及事实回顾中的行动入口，已经把模块连接成可见路径。这个模块的价值不是增加新对象，而是减少用户手动重述经历。这些路径仅在用户主动引用资料时有价值。保存后的即时行动引导和事实回顾中的最近经历行动入口已移除，后续不以推动模块串联为优化目标。

## 已降低的风险与仍存高风险

| 已降低                   | 依据                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| 损坏条目妨碍其余资料抢救 | 可读资料可导出为恢复副本；跳过记录和失效关联会被报告。                   |
| 备份恢复遗漏关键数据域   | 全域备份恢复与恢复后资料可读性已有验收。                                 |
| 未配模型时无法结构化回看 | 本地事实回顾只使用已保存资料和既有关系。                                 |
| 主动引用资料时来源丢失   | 用户选择引用后，行动上下文保留来源、证据、理由与问题；独立行动无需来源。 |
| 搜索只依赖正文关键词     | 已有日期、标签、行动/原则关联筛选和关系回溯。                            |
| 媒体引用被误认为备份本体 | 界面和备份检查区分嵌入数据与仅保留的地址，并可替换网页链接。             |
| 模型答案被误认为资料事实 | 模型辅助、引用数、时间范围、无资料与失败边界均在回答层显示。             |

| 仍存高风险                 | 对产品价值的影响                                                     |
| -------------------------- | -------------------------------------------------------------------- |
| 未完成真实模型评测         | 分身可能错误引用、越过时间范围或给出过度确定的推断。                 |
| 真实设备性能尚未验收       | 合成基准不能替代低端设备上的输入、滚动和内存表现。                   |
| 外链和本机媒体引用会失效   | 地址状态和用户说明虽被保留，外部媒体能否持续访问不受本地控制。       |
| 多个知识对象仍增加学习成本 | 日常路径已连通，但首次用户仍可能不清楚何时使用记录、原则或分身记忆。 |

### 下一步 1：真实模型质量评测（唯一未完成的 P0 门槛）

| 工作                     | 目标                                               | 验收条件                                                     | 边界                         |
| ------------------------ | -------------------------------------------------- | ------------------------------------------------------------ | ---------------------------- |

### 下一步 2：模块独立使用与按需调取

2026-10-09 定位纠偏已落地：保存经历后只提供继续记录和回看入口，不引导立即转成行动；事实回顾只呈现资料，移除从最近经历创建行动的默认建议。未来使用“添加规划”，说明愿望、目标与行动均可独立创建，既有经验和原则仅供按需参考。保留用户主动引用和已有关系，不自动关联、不要求补齐来源。撤销将“经历 → 当前理解 → 下一次尝试 → 结果”作为主路径的设计。

| 工作                 | 目标                             | 验收条件                                           | 范围约束                   |
| -------------------- | -------------------------------- | -------------------------------------------------- | -------------------------- |
| 独立记录、回看与规划 | 每个模块自身即可完成有价值的任务 | 保存后不要求行动；计划无需来源即可创建             | 不把跨模块闭环设为默认目标 |
| 按需引用与来源查看   | 用户引用时可核对所选资料         | 仅展示已有引用；无来源不提示补齐；删除来源状态清楚 | 不自动关联或判定因果关系   |

## 决策顺序

1. 先以用户自行选择并配置的模型完成真实模型评测；在此之前，分身只可作为带边界的可选辅助，不能宣称质量已被验证。
2. 先按模块独立价值与资料按需复用重新评估，检查剩余强关联引导；来源查看只服务用户已经主动建立的引用，不作为强制链路扩展。
3. 再在真实设备上采集性能预算，决定是否需要更进一步的列表虚拟化或索引策略。

不将复杂图谱、成长分数、强制打卡或更多人格标签纳入路线图。这些功能不能直接修复当前资料可靠性、证据链和行动反馈的缺口，且会增加用户维护负担。
