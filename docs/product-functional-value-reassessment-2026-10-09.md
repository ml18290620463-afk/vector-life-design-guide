# Vector 功能价值复评与下一阶段优化建议

评估日期：2026-10-09。工程基线：`main` / `1b5ffc4`（`feat: strengthen deterministic review and backup checks`）。

本文只评估已经交付、可从代码和自动化验收中确认的功能价值。它不把真实用户满意度、留存、付费或外部模型回答质量当作既成事实；这些仍是需要单独验证的假设。早期快照见 [product-functional-value-assessment-2026-10-09.md](product-functional-value-assessment-2026-10-09.md)。

## 结论

Vector 已经不是一个只负责保存日记的资料库。它可以把一段经历保存为可追溯资料，在不配置模型时也能通过确定性筛选和事实回顾找回相关经历，带着明确依据建立行动，再把实践结果记录为下一次理解的证据。

现阶段最实际、也最有差异的价值是：**帮助用户把个人经历变成可核对、可修订、可用于下一次选择的资料资产。** 这项价值不依赖把人归类为人格类型，不依赖成长分数，也不需要强制打卡。用户配置任意兼容模型后，分身可以帮助检索、比较和表达；模型不应代替事实、来源和最终判断。

当前核心闭环已成立，但仍有两个阻断长期信任的缺口：少量损坏资料会妨碍其余资料的抢救；分身的非确定性输出尚未经过真实模型评测。下一阶段应先补足这两处，再降低日常使用中对象概念带来的负担。

## 方法与评分口径

每项维度按 0–10 分评分，综合分按以下权重换算为 100 分。评分用于确定投入顺序，不是市场成绩，也不应以一两分差异作决策。

| 维度             | 权重 | 判断的问题                                       |
| ---------------- | ---: | ------------------------------------------------ |
| 直接任务价值     |  25% | 用户能否完成一个清晰、现实的任务？               |
| 闭环完整性       |  20% | 产物能否成为后续步骤的有据输入？                 |
| 证据与判断可信度 |  20% | 是否保留事实、来源、范围和可修订性？             |
| 操作确定性       |  20% | 本地行为、错误处理和自动化验收是否可靠？         |
| 长期资料资产     |  10% | 数据能否找回、迁移、恢复和长期再利用？           |
| 认知可控性       |   5% | 用户是否能理解当下该做什么，配置和概念是否克制？ |

“操作确定性”与“模型能力”刻意分开：本地检索、资料筛选和备份检查可以被确定性验证；总结、建议与语义理解要由用户自选模型的独立评测决定。

### 经历采集与素材证据：80 分

文本、可选标签与素材使用户能先保留事实，草稿恢复减少中断损失。素材说明由用户亲自补写，可进入搜索与可读文本，系统不擅自理解图片、音频或视频。这是可信资料入口。它仍需要更清楚地区分“素材地址”与“已被备份的媒体本体”。

### 资料找回、筛选与事实回顾：86 分

时间范围、标签、关联行动和关联原则筛选可以组合，10,000 条合成资料的筛选正确性已有测试；搜索还会沿既有关系找回资料。无模型事实回顾只列出记录、既有原则和相关行动，不生成未经证据支持的结论。这是当前最可靠的回看能力。短板从“能否找回”转为大库下的实际响应预算和模糊情境检索表达。

### 原则与理解修订：83 分

原则不是人格结论，而是可追溯、可纠正、可演变的暂时理解；旧版本仍保留背景，当前版本不会混淆。它是产品区别于普通日记的关键。问题是日常界面仍会同时暴露记录、模式、原则和分身记忆等对象，用户需要额外学习它们的关系。

### 行动、实践与结果反馈：86 分

行动可独立创建，也可从记录、搜索结果或原则带入触发情境、依据和问题。实践记录区分完成、部分完成、未完成与调整，且“调整后再做”要求明确下一步。这使“完成率”不再冒充效果。尚缺少从某次实践结果直接、显式地更新或挑战某条原则的闭合交接。

### 分身与用户自选模型接入：71 分

分身会过滤不可访问资料，携带来源、时间和证据；用户可以选择兼容服务商、地址、密钥、模型与接口类型，不依赖固定的 `OPENROUTER_API_KEY` 或 `GEMINI_API_KEY`。计数、范围过滤和事实回顾是本地确定性能力；总结与建议则依赖外部模型。该边界正确，但真实模型尚未用带答案的资料集评估，配置和多个知识对象也提高了首次使用成本，因此它还不是产品信任的基础。

### 连续性：草稿、访问控制、备份恢复：87 分

全域加密备份已覆盖记录、未来数据、原则、理解、关系和缓存；合并幂等、跨密码恢复、错误密码和损坏文件的写前失败均有验收。只读检查能报告加密信封、版本、结构和各数据域数量且不写当前库。这是个人资料资产的强底座。当前恢复更偏“整体安全失败”：一条普通记录无法解密时，尚不能让用户隔离问题并抢救其余可读资料。

### 跨模块编排：86 分

保存记录后的可跳过下一步、从记录/搜索/原则到行动编辑器的 `ActionDraftContext`，以及事实回顾中的行动入口，已经把模块连接成可见路径。这个模块的价值不是增加新对象，而是减少用户手动重述经历。下一步应把路径压缩为日常语言，避免用户在技术对象之间导航。

## 已降低的风险与仍存高风险

| 已降低                             | 依据                                             |
| ---------------------------------- | ------------------------------------------------ |
| 单个资料域读取异常拖垮整个资料展示 | 可读资料采用容错读取，并展示不可读条目原因。     |
| 备份恢复遗漏关键数据域             | 全域备份恢复与恢复后资料可读性已有验收。         |
| 未配模型时无法结构化回看           | 本地事实回顾只使用已保存资料和既有关系。         |
| 行动脱离经历与原则                 | 行动上下文保留来源记录、原则、证据、理由与问题。 |
| 搜索只依赖正文关键词               | 已有日期、标签、行动/原则关联筛选和关系回溯。    |

| 仍存高风险                     | 对产品价值的影响                                             |
| ------------------------------ | ------------------------------------------------------------ |
| 单条普通记录损坏后不能隔离抢救 | 长期资料资产可能被少量坏数据放大为整体不可用感。             |
| 未完成真实模型评测             | 分身可能错误引用、越过时间范围或给出过度确定的推断。         |
| 行动结果未显式回写原则         | 闭环虽有资料关联，用户仍要自行完成“结果改变理解”的关键一步。 |
| 大库只验证筛选正确性           | 10,000 条资料下的渲染、响应时间和内存表现未设产品预算。      |
| 外链和本机媒体引用会失效       | 用户可能误以为备份已保存媒体本体，影响资料证据的长期可用性。 |

## 下一阶段优化路线

### P0：资料可恢复性与模型回答的准入边界

| 工作             | 目标                                                         | 复用基础                                                                      | 验收条件                                                                                              | 范围约束                                                        |
| ---------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 局部损坏资料抢救 | 坏条目不妨碍其他可读资料查看、导出和重新备份                 | `useReadableEntries.ts`、`vaultBackup.ts`、`vaultBackupInspection.ts`、事务层 | 一条故意损坏记录加多条有效记录：有效资料可读、可导出、可备份；界面显示坏条目 ID、失败原因和未写入保证 | 不自动修复或猜测坏数据内容                                      |
| 隔离恢复演练     | 在不写当前资料库的前提下，检验备份能恢复什么、会产生哪些冲突 | 只读备份检查、备份信封解析、恢复映射                                          | 报告各数据域、冲突数、可读性和外链限制；演练前后当前资料库字节级不变                                  | 不把演练结果当作真实恢复，不访问外部链接                        |
| 真实模型评测基线 | 让分身进入可量化的质量门槛，而非凭主观感觉上线               | `avatarQueryPlan.ts`、来源引用、时间范围解析、用户模型配置                    | 使用用户选择的模型与固定开发/留出集，统计来源准确率、时间范围遵守、错误引用率、不确定性表达和失败率   | 不要求固定服务商、固定 API Key 或模型；不以模型分数评价用户成长 |

### P1：完成“经验改变下一次判断”的回路

| 工作                     | 目标                                                           | 复用基础                                                                                           | 验收条件                                                                       | 范围约束                                 |
| ------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| 实践结果到原则的显式交接 | 用户可选择补充、挑战或更新某条原则，并保留实践与原始经历来源   | `PracticeFeedbackFields.tsx`、`principleRevision.ts`、`experienceFeedback.ts`、`sourceDeletion.ts` | 从行动结果选择已有原则后，生成待确认修订；来源可回看；取消不改变原则           | 不自动从一次结果生成结论，不生成成长分数 |
| 日常语言与入口收敛       | 将常规路径呈现为“经历 / 当前理解 / 下一次尝试 / 结果”          | 现有路由、资料页、未来页、分身详情                                                                 | 主路径完成一次闭环时无需理解“模式、记忆、关系”等术语；旧数据和详情关系仍可访问 | 不创建更多人格标签或复杂图谱             |

### P2：规模、媒介与可选模型能力的韧性

| 工作               | 目标                                             | 复用基础                                     | 验收条件                                                                          | 范围约束                               |
| ------------------ | ------------------------------------------------ | -------------------------------------------- | --------------------------------------------------------------------------------- | -------------------------------------- |

## 决策顺序

1. 先完成 P0 的局部抢救、隔离演练与模型评测基线。它们分别保护资料资产和分身可信边界。
2. 再实施 P1 的实践结果到原则交接与入口语言收敛，使现有闭环更容易完成，也更容易被核对。
3. 最后以 P2 的性能基准决定是否投入虚拟列表/索引，并补齐素材引用和模型失败状态。

不将复杂图谱、成长分数、强制打卡或更多人格标签纳入路线图。这些功能不能直接修复当前资料可靠性、证据链和行动反馈的缺口，且会增加用户维护负担。

## 本轮证据

- `features/now/NowFlow.tsx`：记录保存后的下一步与行动上下文。

- `features/future/FuturePage.tsx`、`features/future/PracticeFeedbackFields.tsx`：行动、践行状态与下一步语义。
- `features/now/components/AvatarChatPage.tsx`、`features/now/components/AvatarModelSettings.tsx`、`services/avatarGuidanceSources.ts`：来源边界与用户自选模型配置。
- `services/vaultBackup.ts`、`services/vaultBackupInspection.ts`：恢复与只读备份检查。
- [P0/P1 验收记录](testing/p0-p1-acceptance-2026-10-09.md)：当前功能的针对性测试和浏览器回归证据。
