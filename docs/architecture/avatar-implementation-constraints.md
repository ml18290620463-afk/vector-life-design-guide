# VECTOR「分身（Avatar）」架构实现约束（Architecture Implementation Constraints）

> **文档定位**：本文档是三联架构主图（`01-system-architecture`、`02-request-flow`、`03-memory-lifecycle`）与《VECTOR 分身 v2 系统重构与动态演进开发方案》的**强制工程契约补遗**。
>
> **解决目标**：主图负责界定系统拓扑、信任边界与核心闭环；本文档负责将决定系统真实可靠性的五类底层语义——**原子失效、认知冲突、降级检索边界、撤权删除承诺、并发与故障验证**——固化为可编码、可审计、可自动测试的硬性约束。

> **v2.0 适用性声明（2026-11-25 架构裁决）**：当前分身检索直读统一权威仓库，没有独立异步派生索引或持久检索缓存。因此下文针对独立索引的 `DerivedIndexState`、`Epoch` 失效标记、读取屏障和异步重建 `CAS` 属于 **v2.0 N/A**，不能据此声称已实现或已通过索引重建故障注入。今后若引入向量索引或持久检索缓存，这些条款及 FI-01/FI-02 中的索引时序必须作为上线前强制准入门禁。v2.0 仍须在权威直读链路上执行来源和派生对象的实时权限过滤、请求交付前 token/会话复核、幂等确认、墓碑防复活及有界检索；这些现行边界由自动化测试验证。

## 1. 变更与失效的原子性（Change & Invalidation Atomicity）

核心目标：**杜绝“权威记录已变更但派生索引未失效”的窗口漏洞，杜绝过时重建任务覆盖最新状态。**

### 1.1 单调版本戳与同事务失效（Transactional Invalidation）
1. **单调版本戳（Epoch）**：
   * 每个权威实体（`SourceRecord`、`CognitiveObject`）以及账户级隐私权限状态均维护单调递增的整数版本戳 `$epoch$`（初始为 `$1$`，每次内容编辑、权限变更、锁定、撤权、修订或删除均原子递增 `$epoch \leftarrow epoch + 1$`）。
2. **同事务写入失效标记（Local Outbox 原则）**：
   * 任何来源记录或认知对象的变更、删除、上锁、私密化、撤权，必须在**同一个 IndexedDB 事务**内同步完成两件事：
     1. 提交权威表更新与 `$epoch$` 递增；
     2. 在派生索引元数据表（`DerivedIndexState`）中将所有受依赖影响的索引分片/缓存项标记为 `status = 'invalidated'`，并记录 `requiredEpoch = newEpoch`。
   * **禁止依赖内存事件总线保证正确性**：内存事件（如 `EventTarget` / 回调）仅允许作为“唤醒异步重建”的优化提示；即便页面在事务提交后 1 毫秒崩溃，磁盘上已持久化的 `invalidated` 标记仍能保证重启后绝不读取旧索引。

### 1.2 读取屏障（Read Barrier）
任何派生数据（向量索引命中、摘要、检索缓存）在进入上下文拼装或返回本地查询前，**必须通过三道同步读取屏障**：
1. **状态检查**：目标索引条目不得处于 `invalidated` 或 `stale` 状态。
2. **Epoch 强一致校验**：校验 `derived.sourceEpoch === authoritative.epoch` 且 `derived.objectEpoch === cognitiveObject.epoch`；凡是不一致，该派生条目必须立即丢弃。
3. **实时权限重核**：对命中条目对应的原始来源与派生对象执行运行时权限复核（私密、锁定、封存、加密、撤权、AI 可见性）。

> **不变量**：凡任一屏障未通过，严禁放行该派生条目，且不得将其计入“可用证据”，必须丢弃或触发降级权威兜底。

### 1.3 异步重建的 CAS 防覆写（Compare-And-Swap Promotion）
异步索引重建任务遵循 **Snapshot $\to$ Compute $\to$ CAS Commit** 三阶段协议：
1. **Snapshot**：重建任务启动前，记录当前权威 `$startEpoch$` 及当前账户会话令牌 `$startSessionToken$`。
2. **Compute**：在后台构建新索引/摘要，写入临时槽位（不直接覆盖活跃读取槽位）。
3. **CAS Commit**：准备切换生效时，在提交事务内重新读取 `$currentEpoch$` 与 `$currentSessionToken$`：
   * 仅当 `$currentEpoch === startEpoch$` **且** `$currentSessionToken === startSessionToken$` **且** 账户处于未锁定状态时，才允许原子切换为 `active` 并更新 `indexedEpoch = startEpoch`；
   * 若 `$currentEpoch > startEpoch$` 或会话/锁定状态已变化，**强制中止并丢弃本次重建产物**，严禁旧任务将失效内容重新激活。

### 1.4 崩溃恢复与幂等续跑（Crash Recovery）
* 应用启动、账户解锁或切回前台空闲期，调度器扫描持久化的 `invalidated` / `rebuilding` 标记并触发幂等重建。
* 同一分片同时只允许存在一个活跃重建任务；重复触发合并为单次最新 `$epoch$` 的重建。

## 2. 认知对象的冲突与演化语义（Cognitive Conflict & Evolution Semantics）

核心目标：**让“可版本化”落地为确定、无歧义的认知演化规则，避免错误覆盖或将推断洗白为事实。**

### 2.1 矛盾并存与修订分叉规则
系统不假设人类认知永远单一无矛盾，按以下规则区分**合法并存**与**冲突修订**：

| 冲突情形 | 判定条件 | 系统处理语义 |
|---|---|---|
| **跨场域张力（允许并存）** | 两条认知挂载不同的记录场域标签（`SCOPED_IN` 无交集），例如 `#职场工作` 与 `#家庭关系` | **保留双方活跃**，不触发替代；若存在目标或边界冲突，建立 `TENSION_WITH` 边并在 `decide`/`review` 中显式提示张力。 |
| **跨时效张力（允许并存）** | 一条为 `long_term`（长期底牌），另一条为 `staged`（短期阶段状态，如近期高负荷/低精力） | **保留双方活跃**，优先在当前决策中通过 `TENSION_WITH` 提示短期限制与长期偏好的冲突；阶段状态到期后自动沉降。 |
| **同场域同有效期直接冲突** | 同分类（`category`）、场域重叠且有效时间重叠，陈述语义互斥 | **严禁自动覆盖旧对象**；抽取/整理引擎必须生成 `propose_supersede` 修订候选并绑定 `targetObjectId`，交由用户显式确认是否替代。 |

### 2.2 推断身份的永久保留（Permanent Epistemic Identity）
1. **确认不改性质**：用户显式确认一条来自「我的认识（`my_understanding`）」的推断候选后，仅发生生命周期跃迁（`candidate` $\to$ `confirmed`），其**认识论身份永久不变**：
   * `domain: 'my_understanding'`、`origin`（推断/提炼/手动）、`evidenceGate` 快照与 `EVIDENCED_BY` 证据链永久保留；
   * 严禁将已确认的推断“升级/洗白”为第一人称客观事实记录或「关于我」的直接自述。
2. **导入材料身份隔离**：来自外部导入或摘录的材料在 `SourceRecord` 中永久标注非本人说话人/导入来源标识，**绝不自动等同于本人观点**，除非用户另有明确的第一人称表达或显式确认关联。

### 2.3 替代触发点与谱系不变量
1. **唯一替代入口**：仅当用户在前端显式触发确认修订动作时，记忆服务在同一事务中执行：
   * 创建新对象（`version = prev.version + 1`，继承 `lineageId`）；
   * 写入 `SUPERSEDES` 有向边（`newId` $\to$ `prevId`）；
   * 将旧对象状态置为 `superseded`，退出默认活跃检索池；
   * 递增相关 `$epoch$` 并触发关联派生索引失效。
2. **谱系完整性**：拒绝同 `lineageId` 下重复 `version`；拒绝 `$version > 1$` 但缺少有效前序 `SUPERSEDES` 边的孤儿对象。
3. **「我的变化」只读契约**：「我的变化」仅由 `SUPERSEDES` 边实时投影，不提供手动新增入口，且永久保留边界说明（观点修订 $\neq$ 已证明的成长）。

### 2.4 阶段性状态到期沉降
* 当系统时间满足 `$t_{\text{now}} > t_{\text{validUntil}}$` 时，`validity.mode === 'staged'` 的对象自动沉降为 `archived_expired`。
* `archived_expired` 对象退出默认活跃抽牌池，仅在显式跨周期 `recall` / `review` 中以“历史阶段状态”标签被回溯，严禁作为用户当前现状注入提示词。

## 3. 降级检索的服务目标与边界（Degraded Retrieval SLO & Boundaries）

核心目标：**在“先失效，再异步重建”的窗口期内，明确兜底扫描的延迟、覆盖面与诚实降级契约。**

### 3.1 触发条件
当本次查询所依赖的任一派生索引分片处于 `invalidated`、`rebuilding`、`missing` 或命中 `epoch` 失配时，自动进入**降级权威检索路径**。

### 3.2 分级权威兜底与硬预算（Hard Budgets）
降级检索**绝不回退读取失效索引**，而是直接经由记忆服务扫描本地权威数据，并执行两级硬预算控制：
1. **Tier A · 统一认知对象全量兜底**：
   * 对当前账户下处于 `confirmed` 态、未过期且通过权限重核的 `CognitiveObject` 执行权威扫描（个人认知对象体量通常在百级以内，保证核心底牌与个人护栏不丢失）。
2. **Tier B · 原始记录受限倒序兜底**：
   * 对 NOW / Past / Future 原始记录按发生时间倒序执行关键字/标签/时间范围匹配，受以下双硬预算约束（先到即停）：
     * **扫描条数上限**：默认 `$N_{\max} = 200$` 条最近可访问记录（用户点击【扩大范围重新参考】时可放宽至 `$N_{\text{expanded}} = 600$` 条）；
     * **耗时上限**：单次兜底扫描硬超时 `$T_{\max} = 300\text{ ms}$`。

### 3.3 超时与截断行为
* 达到 `$N_{\max}$` 或 `$T_{\max}$` 时，立即停止扫描并返回当前已命中的权威结果子集。
* **禁止行为**：
  * 禁止无限阻塞对话主链路；
  * 禁止在未经用户触发的情况下将同步问答悄悄改为异步延迟推送覆盖新对话；
  * 禁止用已失效的旧索引结果“补齐”截断部分。

### 3.4 强制白盒降级声明（Manifest Contract）
`GuidanceRetrievalManifest` 必须显式透出降级状态，供前端白盒证据条渲染：

```ts
export interface RetrievalDegradationMeta {
  /** 本次检索是否触发了权威降级兜底 */
  degraded: boolean;
  /** 降级原因（仅 degraded === true 时存在） */
  degradedReason?:
    | 'index_invalidated'
    | 'index_rebuilding'
    | 'fallback_budget_reached';
  /** 覆盖完整性声明：严禁将不完整兜底伪装成完整检索 */
  coverageStatus: 'complete' | 'partial_authoritative';
  /** 降级时实际扫描的权威原始记录数 */
  scannedRawRecordCount?: number;
  /** 降级扫描实际耗时（毫秒） */
  fallbackDurationMs?: number;
}
```

当 `degraded === true` 时，前端证据条必须明确告知用户当前检索处于降级/部分覆盖状态（例如：“索引重建中，本次仅参考活跃认知与最近 200 条权威记录”）。

## 4. 撤权、删除与恢复的承诺矩阵（Revocation, Deletion & Recovery Matrix）

核心目标：**如实界定各存储介质上的安全能力边界，并防止恢复旧备份时导致已删除或已撤权内容静默复活。**

### 4.1 四级存储边界承诺表

| 存储位置 | 撤权（私密/锁定/关闭 AI 可见）承诺 | 删除承诺 | 诚实边界说明 |
|---|---|---|---|
| **1. 本地权威存储**<br>*(IndexedDB 主库)* | **同事务立即生效**：后续一切 AI 检索与本地查询均实时拦截原记录及其派生依赖。 | **同事务彻底物理删除**原记录，并写入无原文的删除墓碑；依赖该来源的认知按影响预览级联处理或转为 `retained_after_source_delete`。 | 受控域内强保证。 |
| **2. 本地派生数据与缓存**<br>*(索引/摘要/会话缓存)* | **同事务标记失效**：读取屏障立即阻断旧索引命中，随后异步重建剔除受限内容。 | **同事务标记失效并清理缓存**，旧重建任务受 CAS 拦截不得回写。 | 受控域内强保证。 |
| **3. 加密备份与导出文件**<br>*(用户本地磁盘/云盘静态文件)* | 仅作用于**此后新生成的备份**；已导出的历史静态文件不会被远程修改。 | 仅作用于此后新备份；通过本地墓碑机制阻止历史备份导入时静默复活。 | 静态副本由用户自行保管与销毁，系统明确提示。 |
| **4. 外部模型服务商**<br>*(外部服务域)* | 立即停止后续外发；在途请求后置复核拦截并丢弃响应展示。 | 立即停止后续外发。 | **诚实声明**：中止或撤权无法撤回此前已发往第三方服务商的数据；保留期限以对应服务商政策为准。 |

### 4.2 防旧备份“僵尸复活”机制（Anti-Resurrection Tombstones）
1. **无原文墓碑结构（Zero-Plaintext Tombstone）**：
   * 为避免墓碑本身成为隐私泄露源，墓碑仅存储单向哈希 ID 与操作时间戳，**严禁保存任何标题、摘要或原文片段**：

```ts
export interface DeletionTombstone {
  /** SHA-256(accountSalt + entityKind + entityId)，不暴露原始语义 */
  entityIdHash: string;
  entityKind: 'source_record' | 'cognitive_object' | 'ontology_edge';
  opType: 'deleted' | 'ai_revoked';
  occurredAt: string; // ISO 8601
  schemaVersion: number;
}
```

2. **导入与同步拦截规则**：
   * 导入历史备份或执行跨端同步时，对每条待导入记录计算 `entityIdHash` 并比对本地墓碑；
   * 若命中墓碑且 `$tombstone.occurredAt > incoming.updatedAt$`：
     * **默认拦截**：禁止静默恢复该条记录或其派生认知；
     * **显式交互确认**：在恢复预览界面汇总展示“检测到 `$K$` 条记录在备份之后已被删除或撤权”，默认选项为**保持已删除/已撤权**，仅在用户主动勾选“显式恢复旧版本”时才解除对应墓碑。

### 4.3 `retained_after_source_delete` 的严格适用范围
* 仅适用于**用户显式删除原始来源并勾选保留派生认知**的场景，且强制设置 `privacy.traceabilityDegraded = true`。
* **严禁滥用于撤权或锁定场景**：当来源是被设私密、上锁、加密或撤销 AI 权限（而非删除）时，派生认知必须随权限连坐被动态隔离，绝不能通过此状态绕过访问限制。

## 5. 并发与故障验证矩阵（Concurrency & Fault-Injection Matrix）

所有约束最终必须通过确定性自动化测试验收，严禁仅靠代码走查宣称满足。

### 5.1 优先级最高：黄金并发验收场景（Golden Concurrency Scenario）
**测试场景**：*来源修订或撤权，与正在进行的检索及异步索引重建并发发生*。

必须落地为确定性 Vitest 自动化测试，严格验证以下四步时序与断言：

1. **T0 · 初始态与在途请求启动**：
   * 权威库存在原文 `S1`（`$epoch = 1$`）、派生已确认认知 `C1`（`EVIDENCED_BY` $\to$ `S1`），以及有效检索索引 `I1`（`indexedEpoch = 1`）。
   * 发起语义问答请求 `R1`，携带权限令牌 `token_1`；通过受控 Promise 让外部模型适配器在返回前挂起。
2. **T1 · 并发启动旧重建 + 实时撤权**：
   * 启动一个基于 `$startEpoch = 1$` 的异步索引重建任务 `Job_stale` 并挂起其提交步骤。
   * 在 `R1` 与 `Job_stale` 均未完成时，用户对 `S1` 执行撤权/设私密（或修订删除）：同事务将 `S1.epoch` 递增至 `$2$`，并立即将 `I1` 标记为 `invalidated`（`requiredEpoch = 2`）。
3. **T2 · 过时产物回流拦截**：
   * 放行 `Job_stale` 提交 $\implies$ **断言**：CAS 检测到 `$currentEpoch(2) > startEpoch(1)$`，拒绝切换，丢弃旧索引产物，`I1` 保持 `invalidated`。
   * 放行 `R1` 的模型响应返回 $\implies$ **断言**：交付前复核检测到 `token`/权限或依赖 `$epoch$` 变更，立即中止并丢弃响应，不展示旧回答，不写入任何候选，并向前端返回明确中断提示。
4. **T3 · 紧随其后的新检索验证**：
   * 在新重建完成前，立即发起同一问题的新请求 `R2` $\implies$ **断言**：读取屏障拦截失效索引 `I1`，触发降级权威兜底；`S1` 与派生认知 `C1` 均被权限连坐剔除；`R2` 的白盒 `GuidanceRetrievalManifest` 中 `degraded === true`、`coverageStatus === 'partial_authoritative'`、`filteredOutByPrivacyCount >= 1`，**零泄露旧内容**。

### 5.2 五大故障注入测试清单

**v2.0 执行口径**：FI-01 的在途撤权/修订、旧响应丢弃和后续权威直读过滤仍为必测；其中“旧索引不可读、旧重建 CAS 失败”不适用。FI-02 全项不适用，因为运行时不存在异步索引重建。FI-03～FI-05 按现行权威直读与恢复事务验证。81 项故障边界相关测试的通过结果只证明其实际断言，不等同于对 N/A 索引情形的模拟通过。

| 编号 | 故障/并发场景 | 必验不变量 | 目标落地阶段 |
|---|---|---|---|
| **FI-01** | 黄金并发场景：来源撤权/修订 vs 在途检索 | v2.0 必测旧响应丢弃、新查询零泄露；旧索引不可读与重建 CAS 为 v2.0 N/A，未来引入索引时必测 | **v2.0 直读边界必过；索引部分 N/A** |

## 6. 与 Phase 2–5 重构路线的挂载映射

为避免单阶段范围失控，上述约束按阶段拆解吸收，各阶段严格只实现对应切片：

| 约束条目 | Phase 2（当前 · 检索与漏斗） | Phase 3（增量抽取与冲突） | Phase 4（治理与 UI 收口） | Phase 5（清残留与总验收） |
|---|---|---|---|---|
| **1. 原子失效与 Epoch/CAS** | v2.0 权威直读：落实来源权限过滤与请求交付前 token/会话复核；独立索引 Epoch/CAS 为 N/A | 修订确认后继续直读权威版本并重核权限；不创建索引重建任务 | 如有直读降级，展示诚实的部分覆盖提示；无索引重建状态 | 回归直读并发边界；将 Epoch 失效与重建 CAS 留作未来索引上线准入 |
| **2. 冲突与演化语义** | 落地阶段状态到期沉降退出活跃检索池 | **落地核心机制**：跨场域并存 `TENSION_WITH`、同场域冲突分叉、推断身份永久保留 | 「我的变化」只读投影与推断标识 UI 呈现 | 全量语义边界回归 |
| **3. 降级检索 SLO** | **落地核心机制**：两级兜底、`$N_{\max}/T_{\max}$` 硬预算、`GuidanceRetrievalManifest` 降级字段 | 抽取前查重复用统一读取屏障 | 证据白盒条展示降级/部分覆盖提示 | 性能与预算边界回归 |
| **4. 撤权/删除与防复活** | 保持 Phase 1 权限连坐与删源边界不退化 | — | **落地核心机制**：无原文墓碑 `DeletionTombstone`、备份导入防复活预览、四级边界诚实文案 | 跨版本备份恢复端到端回归 |
